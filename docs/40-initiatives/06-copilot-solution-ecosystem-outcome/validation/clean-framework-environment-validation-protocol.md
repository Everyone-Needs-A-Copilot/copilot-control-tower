# Clean framework environment validation protocol

Status: protocol only; not executed
Task: TASK-303
Acceptance criterion: AC-18F

## Purpose

Prove that the framework itself—not the Control Tower app—can establish and
continue the complete Claude + Codex problem-to-solution environment in an
isolated clean user home. The run covers canonical setup, entitlement,
materialization, lock provenance, specialist routing, bounded operational
capabilities, update/fan-out consumption, and Task Copilot continuation.

## Entry gate

- TASK-285 has accepted the controlled effectiveness artifacts.
- TASK-297 has released owner-approved immutable organization/accounting inputs.
- TASK-299 has accepted post-fan-out entitlement and boundary security.
- Record the exact framework commit/tree, signed layer refs/trees, signer policy,
  evaluation fixture digest, and approved census identity.
- Use a dedicated isolated home or disposable account. Do not delete or reset an
  existing home to manufacture the condition.

## Procedure

1. Establish an empty dedicated home with no copied caches, credentials,
   checkouts, materialized content, lock, or Task Copilot state.
2. Install the exact framework revision through its documented supported setup
   path. The operator may use the terminal for provisioning; no app artifact is
   installed or required.
3. Complete ordinary GitHub entitlement and verify explicit entitled,
   unentitled, offline, stale, revoked, and recovered behavior with approved
   fixtures. Never record credential values.
4. Create the reference synthetic project through the canonical transaction.
   Verify Claude/Codex materialization, immutable source identity, destinations,
   and canonical lock postconditions.
5. Run the representative problem through protocol routing, the expected
   specialist sequence, bounded `copilot` capabilities, and `tc` evidence.
6. End the session, then resume from `tc` without copied state or manual
   repository wiring. Verify the next action and prior evidence are recoverable.
7. Apply one exact approved shared update through the canonical `cc` path.
   Verify the completed-actions ledger, postconditions, and preserved project
   work. Exercise one dirty/ambiguous fixture and prove it is held unchanged.
8. Run full conformance and the applicable evaluation identity checks. Preserve
   raw JSON, redacted manifests, and artifact digests for independent QA.

## Hard gates

- No manual file copying, symlink repair, repository reset, lock edit, or hidden
  publisher-home dependency.
- Exact immutable organization/accounting inputs win and appear in lock/runtime
  evidence for entitled cases; protected inputs fail closed when unavailable.
- Personal content, credentials, and unrelated project work never move upward.
- Routing, operational capability use, and Task Copilot continuation are proved
  by artifacts rather than a narrative assertion.
- A blocked or unknown state remains blocked/unknown and names the competent
  actor; it never becomes a fabricated pass.
- The app, its signing identity, notarization, Installer package, and publisher
  bootstrap are absent from the prerequisite and verdict.

AC-18F passes only after both execution and independent QA produce linked,
content-addressed evidence. This protocol does not prove app installation,
general availability, or non-technical participant success.
