What changed

Technical readiness is the current product of work.

The original ambition remains: ordinary people should eventually receive a trustworthy, company-aware solution team. The delivery sequence is different now. First, Pablo gets the technical ecosystem working and uses it. That lived experience will determine what the later app should do.

Why no self-approval: GitHub cannot let an author approve their own pull request. The correct solo-owner design is zero required approvals plus technical checks—not a manufactured self-approval or an external reviewer dependency.

Realistic verification

Twelve scenarios prove the chain Pablo will actually use.

Open a scenario to see its purpose and evidence. The suite begins with ordinary problems, not prompts designed to name internal components.

S-01Start with a problem and route it

Give Claude Code and Codex a vague service, organizational, interface, or accounting problem. Protocol chooses the specialist sequence, explains it, asks only necessary questions, and avoids beginning with infrastructure.

Evidence: prompt, runtime, route events, specialists, rejected alternatives, task record.

S-02Assemble the entitled pieces

Run foundation, organization, accounting, and synthetic-personal variants. Resolution, source identity, Claude/Codex materialization, Knowledge receipts, capabilities, and lock/disk state agree.

Evidence: resolver explanation, receipts, inventory, lock, disk hashes, parity map.

S-03Apply the work and create something

Create a self-contained brief, blueprint, implementation slice, interface specification, or accounting evidence package. Layered context changes decisions—not merely vocabulary—and the project owns the result.

Evidence: foundation/layered artifacts, criterion verdicts, project tree, ownership.

S-04Preserve and continue

Pause, end the process, and resume in a fresh session. Task Copilot recovers next action, decisions, evidence, questions, artifacts, and identities without a reconstructed mega-prompt.

Evidence: pre-pause state, handoff, fresh-process transcript, resumed action, idempotence.

S-05Keep working through a shared update

Apply an immutable shared update through cc update. Managed content changes; human work remains byte-identical; receipts, lock, and ledger record the new source.

Evidence: before/after trees, released ref, ledger, preservation hashes, rollback.

S-06Hold dirty or ambiguous work safely

Exercise tracked, untracked, staged, customized, interrupted, and link-escape states. Preflight holds before destructive mutation and names recovery.

Evidence: fixture matrix, hashes, bounded ledger, held-state JSON.

S-07Exercise entitlement and connectivity

Run entitled, unentitled, offline, stale, revoked, and reauthorized states. Protected content fails closed and recovery restores an approved immutable source.

Evidence: transitions, sanitized probes, active state, recovery.

S-08Exercise operational failures

Run available, missing, timed-out, malformed, and security-denied capabilities. Optional services fail open; mandatory security denies before execution; secrets stay out of evidence.

Evidence: invocation, result contract, redaction, continuation or denial.

S-09Reject provenance and boundary attacks

Inject unsigned or moved refs, wrong signers, missing paths, tampered locks, secrets, cross-tier writes, personal markers, unsafe links, and mismatched bytes.

Evidence: positive controls, negative fixtures, filesystem proof, security verdict.

S-10Prove Claude/Codex intent parity

Run the same eligible cases in both runtimes. Purpose, specialist intent, Knowledge use, safety, ownership, and durable output agree. Unsupported surfaces are explicit.

Evidence: parity table, runtime/plugin identities, artifacts, decisions.

S-11Propagate across the approved fleet

Regenerate the census, obtain Pablo's approval, pilot, and update only eligible clean projects. Hermes and held repositories remain outside the mutation set.

Evidence: census, approval, pilot, ledgers, exclusions, post-reports.

S-12Reproduce everything in a clean environment

From an empty home, install, authenticate, create, preserve, resume, update, recover, and conform. Control Tower is absent.

Evidence: inventory, install transcript, identities, artifacts, update/recovery, independent QA.

Coverage model

Risk-based cells replace vague “end-to-end” claims.

Axis Required cells
Runtime Claude Code; Codex; explicit unsupported decision
Layers Foundation; + organization; + accounting; synthetic personal where allowed
Lifecycle Fresh; idempotent reinstall; update; pause/resume; recovery
Entitlement Entitled; unentitled; offline; stale; revoked; reauthorized
Project state Clean; tracked dirty; untracked; staged; customized; interrupted; link boundary
Trust Valid signed; unsigned; wrong signer; moved/mutable; missing path; mismatched bytes
Capability Success; optional missing; timeout; malformed; mandatory denial

No aggregate score. Any hard safety, privacy, or ownership violation fails its case regardless of other passes.

Merged, signed, pinned, installed, and byte-matched framework and content.

Integrated security
