## 3. Fitness tests genuinely guard — mutation-spot-checked, not just read

Read all nine M9 fitness test files (35 individual `#[test]` functions across
`fitness_m9_platform_windows_cfg_gated.rs`,
`fitness_m9_windows_{cli_path_no_path_env,forced_never_reads_hkcu,
loginitem_gated_on_managed_config,secret_store_no_secret_leak,
tray_reuses_badge_table,uninstall_task_names_match,verify_pre_promote,
watchdog_no_periodic_trigger,wix_no_alluser_1}.rs`). Each maps cleanly to one
invariant (crash-only, forced-domain, secrets, parse-not-compute tray,
never-orphan uninstall, dispatch-not-decide). Live-mutated two of the cheapest
ones to confirm they are not tautological:

- **Watchdog no-periodic-trigger:** injected a live `<TimeTrigger>` into the
  checked-in `packaging/taskscheduler/controltower-watchdog.xml`. The test
  `the_checked_in_task_xml_template_never_contains_a_periodic_repeat_trigger`
  failed immediately with the expected message ("this IS the forbidden
  resurrect-always anti-pattern"). Reverted; re-ran clean (5/5 passed).
- **Forced no-HKCU:** injected a literal `"HKCU"` string into
  `platform/windows/forced.rs`'s production code (inside
  `dsregcmd_absolute_path`, outside any comment/test block). The test
  `windows_forced_reader_never_references_hkcu_fitness_m9` failed
  immediately with the expected message. Reverted; re-ran clean (3/3 passed),
  confirmed no diff remains (`grep` for the mutation marker returns nothing).

Both mutations caught on the first run, no false negatives. Confirms the
"cheap text-scan" fitness style this crate already uses (per
`fitness_m5_single_forced_boundary.rs`'s precedent) is not vacuous here.

## 4. Code review against the parity doc + invariants

Reviewed every `platform/windows/*.rs` seam (`cli_path`, `forced`,
`loginitem`, `schtasks`, `secret_store`, `tray`, `watchdog`), the WiX/winget
packaging config, `scripts/sign-windows.ps1`, and
`updater::verify`'s `verify_authenticode`/`verify_pre_promote` dispatcher,
line-by-line, against `windows-parity.md` §1's 11-row table and CLAUDE.md's
invariants. Findings:

- **No seam computes a verdict it shouldn't** — tray recolors RGB only
  (alpha/shape untouched, reuses `render::glyph::composite` verbatim); the
  `verify_pre_promote` dispatcher only routes, never re-decides.
- **No seam resurrects-always** — the watchdog XML has exactly one
  `<LogonTrigger>` plus `<RestartOnFailure>`, no periodic trigger (fitness +
  mutation-verified above); the separate logon-trigger login-item task
  (`loginitem.rs`) carries no `<RestartOnFailure>` of its own (source-scan
  confirmed, and this task's own fitness test proves `register()` is gated,
  `unregister()` is unconditional).
- **No seam reads a user-writable domain for security config** —
  `forced.rs` reads `HKEY_LOCAL_MACHINE` only; `HKCU`/`HKEY_CURRENT_USER`
  never appears in its production source (mutation-verified). `dsregcmd` is
  resolved via an absolute `%SystemRoot%\System32\dsregcmd.exe` path, never a
  bare `PATH` lookup — this was itself a sec-review-driven fix (see below).
- **No seam holds a secret** — `secret_store.rs` deliberately implements
  ONLY the endpoint-reference half (`SecretStoreRef { url, tier }`); it never
  calls Credential Manager/DPAPI/`keyring`, matching the ratified scope
  (`platform::PlatformSecretStore`'s own doc, `credentials-and-boundary.md`
  §3's ownership table: CLI "Owns it," Control Tower "No role"). This was a
  deliberate scope decision recorded and reviewed, not an oversight.
- **No seam uses a bare/`%PATH%` name** — `cli_path.rs` never reads
  `%PATH%` (fitness-tested); resolves via `current_exe()`-relative first,
  registry fallback second; hardens the DLL search order via
  `SetDefaultDllDirectories` (unverified binding signature, honestly flagged).
- **No seam orphans on uninstall** — the WiX uninstall custom action fires
  only on genuine removal (`REMOVE="ALL"` AND NOT `UPGRADINGPRODUCTCODE`,
  never mid-upgrade); task names in the custom action are cross-checked
  (fitness-tested) against `loginitem.rs`/`watchdog.rs`'s own constants to
  prevent drift.
- **Honestly-flagged residuals found in the code/docs, not glossed over:**
  (1) the BYOD self-enrollment weakness — a local admin can self-service
  domain-join a lab AD/free Azure AD tenant, after which `dsregcmd`
  legitimately reports "enrolled," indistinguishable from genuine org
  enrollment (sec-reviewed, `tc wp get 57`, ACCEPT-with-residual, NOT
  closed); (2) SmartScreen has no staple equivalent — a freshly EV-signed
  binary can still show the interstitial until reputation accrues; (3)
  Task-Scheduler hang/retry-interval tuning is reused, unvalidated macOS
  constants, explicitly named as owner-gated in ADR-M9-006.
- **A genuine, previously-undocumented scope gap found this pass:**
  notifications (`windows-parity.md` §1 row 8 / §3 item 4) has a recorded
  *decision* (fallback-to-IT-channel as primary) but **no code at all** —
  confirmed by grep: no `tauri-plugin-notification` dependency in
  `Cargo.toml`, no toast-wiring source file anywhere in `src-tauri/src/`.
  This is flagged as a real M9 scope gap in the matrix below, not silently
  folded into "owner-gated" alongside the other, genuinely-code-complete
  rows.

binary scan, not just source-scan), macOS is genuinely unregressed (860/861
