    <section id="findings">
      <p class="section-kicker">Why the answer is no</p>
      <h2>Five findings decide the verdict</h2>
      <div class="finding-grid">
        <article class="finding">
          <span class="number">1</span>
          <h3>The mechanism exists; the outcome does not</h3>
          <p>A synthetic organization marker reaches a scratch project, but no real organization or department content wins attribution and no behavioral evaluation shows real output changing.</p>
        </article>
        <article class="finding">
          <span class="number">2</span>
          <h3>Installer ownership is still split</h3>
          <p>Claude setup does not install Codex. <code>cc workspace</code> and <code>/setup-project</code> also materialize different Claude command sets.</p>
        </article>
        <article class="finding">
          <span class="number">3</span>
          <h3>“Full” omits the layer with another S0</h3>
          <p>The design says full mode includes round-trip; the shipped CLI makes it opt-in. An operator following the README misses the end-to-end failure.</p>
        </article>
        <article class="finding">
          <span class="number">4</span>
          <h3>The regression baseline is stale</h3>
          <p>The comparison reports 515 fixes, 132 still failing, 82 PASS→FAIL changes, and 16 new failures. Intentional decisions and real drift are no longer reconciled.</p>
        </article>
        <article class="finding">
          <span class="number">5</span>
          <h3>The handoff evidence has drifted</h3>
          <p>Operator docs describe the CLI as unlanded, test counts and commands are stale, and the referenced PRD-22/tasks 264–276 are absent from the current task database.</p>
        </article>
      </div>

      <ul class="good-list">

        <li>Found shell, lock, waiver, provenance, staleness, and tier-resolution defects that code reading missed.</li>
        <li>Introduced the crucial INSTALLED / WIRED / EFFECTIVE distinction.</li>

    <section id="closure">
      <p class="section-kicker">What “done” now requires</p>
      <h2>A decision-ordered path to closure</h2>
      <ol class="steps">
        <li><strong>Choose one canonical install transaction.</strong> It must produce the complete Claude + Codex reference install.</li>
        <li><strong>Make end-to-end verification truly full.</strong> Include round-trip and prove degraded-install repair plus final Layer-3 parity.</li>
        <li><strong>Fix the three E-4 S0 mismatches.</strong> Repair personal-tier plugin lock recording; do not weaken the check.</li>
        <li><strong>Reconcile and regenerate the baseline.</strong> Separate ratified changes from genuine regressions, then update static expected-state metadata.</li>
        <li><strong>Author real organization and department content.</strong> Include substantive agent/command contributions and the missing <code>uids</code>/<code>cco</code> extensions.</li>
        <li><strong>Add behavioral effectiveness evidence.</strong> Compare controlled agent runs with and without nearer-tier content.</li>
        <li><strong>Repair the durable record.</strong> Update operator docs and recover or explicitly retire the missing task provenance.</li>
        <li><strong>Re-run to a meaningful closure state.</strong> Require zero S0, zero unexplained unknowns, and zero unreviewed baseline regressions.</li>
      </ol>
    </section>
