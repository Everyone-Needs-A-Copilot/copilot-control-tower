# T50 (M5-S7) — M5 QA acceptance gate (Copilot Control Tower MDM & Security)

QA engineer: independent adversarial verification of the whole M5 MDM/
security plumbing (S1–S6: forced-domain boundary, deprovision parse-not-
compute, route-by-competence, login-item vs watchdog, `.mobileconfig`
generator, secret-store endpoint reference). Everything below was actually
**run**, not asserted from reading code, including two live mutation
tests that confirmed FF-M5-1 and FF-M5-2 genuinely fail when the invariant
they guard is deliberately broken (and pass again once byte-for-byte
restored). One real, evidence-based scope gap was found and **reported**
(task 50's own filed acceptance criteria named three deliverables —
`tests/integration_m5_managed_deprovision.rs`, `tests/fitness_m5_suite.rs`,
`docs/06-deployment/m5-owner-gated-batch.md` — that were never built by a
prior session); the third was **fixed** this session (small/safe, pure
documentation, directly requested by this task's own deliverable section).
One environment quirk (a stale, pre-session `target/release` binary
initially producing a false-positive dev-seam `strings` hit) was
investigated and resolved as a non-issue via a clean rebuild.

**Environment note (not a repo defect, same as M4 QA's own finding):**
`/Users/pabs/.local/bin/cc` shadows `/usr/bin/cc` on `$PATH`, breaking every
`cargo build --release`/`cargo clippy --release` (`aws-lc-sys`'s C compiler
probe fails with `cc: No such option: -O`). Worked around for this session
only via `PATH="/usr/bin:$PATH" CC=/usr/bin/cc` on every release-profile
cargo invocation — no repo file changed.

including two LIVE mutation tests (not merely read-and-trust) proving
