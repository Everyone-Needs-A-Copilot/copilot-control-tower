# Org-Tier Config Migration — Classification, Mechanism, Sequence

## ADR-001: How each org `.env` key becomes regen-safe
**Status:** Proposed
**Context:** Org mirror `.env` is a symlink to the git-ignored working-tree `.env`;
`copilot update` would clone the repo (no `.env`) and drop all 39 keys. Two consumer
classes; a mechanism gap blocks non-secret *provides* config.
**Decision:** (1) Extend the overlay schema so `provides[]` accepts a `config:` block that
`TierConfigSource` (and `managed_store._find_store_layer`) fold, symmetric with `adopt[]`.
(2) Non-secret Class-1 config → committed overlay `config:`. (3) Secret Class-1 → managed
store via `requires_secret`. (4) Class-2 (infisical/coolify self-contained) handled per
ADR-002. (5) Drop 15 dead keys and 6 default-equal keys.
**Consequences:** Easier: committed repo alone yields a full mirror; provides config
inherits down-tier like adopt config. Harder: one small foundation (cli-copilot) change is a
prerequisite; a silent-drop footgun (config on provides) is closed. Reversible: yes — additive
schema field + additive fold; `.env` retained until scratch-mirror verify passes.
**Alternatives Rejected:** (a) Put provides config under an `adopt[].config` block — works
mechanically (flat field-name match) but semantically misplaces org-service config under a
base service and keeps the silent-drop footgun. (b) Keep non-secret config in `.env` — defeats
the goal. (c) Ship a committed `.env.public` non-secret file the mirror reads — reintroduces a
second config home competing with the overlay and the ratified `config:` mechanism.

## ADR-002: Class-2 self-contained services (infisical, coolify)
**Status:** Proposed (owner decision required)
**Context:** `InfisicalSettings` and coolify `APIConfig` bypass the layered chain; they read
env/`.env`/TOML/`.mcp.json`. Overlay `config:`/`requires_secret:` never reaches them.
- INFISICAL_BASE_URL: the store gate (`managed_store._find_store_layer`) already folds the
  committed `adopt.config.infisical_base_url` (regen-safe); only the `copilot infisical`
  service subcommands (InfisicalSettings) still need the value from env.
- COOLIFY_BASE_URL (non-secret) + COOLIFY_API_KEY/ACCESS_TOKEN (secret): read only by
  `APIConfig`; the overlay's `requires_secret: COOLIFY_ACCESS_TOKEN` is INERT today.
**Decision (recommended):** Teach each self-contained loader to consult the layered chain as a
fallback: base_url from the tier `TierConfigSource`; secret via the credential ladder
(`resolve_secret`). This makes `requires_secret: COOLIFY_ACCESS_TOKEN` live and both services
regen-safe with no `.env`.
**Alternatives Rejected:** (a) Coolify token in `~/.coolify-cli/config.toml` — per-user
bootstrap (like keychain), outside git, but coolify-specific and inconsistent with the ladder.
(b) Inject via process env from a launcher — reintroduces an out-of-band config carrier.
**Owner call:** approve the loader-consults-ladder change vs. accept coolify TOML/keychain
bootstrap.

## Mechanism check summary
- Non-secret ADOPT config: `TierConfigSource` reads `adopt[].config` (settings.py:150-156) →
  works today for git/uspto (and infisical already).
- Non-secret PROVIDES config: NOT read (parser drops it, layers.py:463-475) → ADR-001 fix.
- Secret via `requires_secret` (adopt or provides): `all_requires_secret()` spans provides
  (layers.py:335-351); `SecretRefSource` resolves by field_name.upper() → works today.
- Store target: Infisical project as used by already-migrated secrets — overlay comments say
  `copilot-ecosystem / prod / /shared` (N8N_API_KEY, NOCODB_API_KEY, BREVO_API_KEY,
  INSIGHTS_API_KEY, PROJECT_COPILOT_API_KEY, CONVERSATIONS_AGENT_AUTH_SECRET). Store gate =
  committed `adopt: infisical config:` (workspace/env/path already migrated in Phase 4 #1).
- Class-2 bypass both folds (infisical/coolify) → ADR-002.

## Batches / sequence
- **Batch 0 (foundation, prerequisite):** ADR-001 mechanism — add `config:` to `OverlayProvide`,
  fold in `TierConfigSource` + `managed_store._find_store_layer`. cli-copilot change. Unit tests.
  Verify: scratch overlay with a provides `config:` surfaces the field in overlay `Settings`.
- **Batch 1 (non-secret, lowest risk):** groups A (drop), B (adopt config), H (drop machine path),
  G (drop dead). Verify per adopt/provides service resolves from committed config with NO `.env`.
- **Batch 2 (non-secret provides config):** group C (needs Batch 0). Verify discord/nocodb/
  project/conv resolve base_urls/ids from committed provides `config:` with NO `.env`.
- **Batch 3 (secrets):** group D → store (per-service verify); ADR-002 for group E/F (coolify
  token + base_urls; infisical service base_url). Verify each service authenticates with NO `.env`.
- **Batch 4 (regen cutover):** remove the `.env` symlink; build a scratch mirror from a fresh
  clone (no `.env`); run the full per-service verify; only then declare the mirror regen-safe and
  retire the hand-placed mirror.

## Per-batch verification commands (resolve from a NO-`.env` scratch mirror)
- git: `copilot git config` reflects committed name/email.
- nocodb/crm: `copilot crm ...` (nocodb_url/base_id + NOCODB_API_KEY from store).
- discord: bridge/handoff resolves channel/allowed-users from committed config; DISCORD_BOT_TOKEN
  from keychain.
- project: `copilot project ...` resolves base/web url + agent secret + browse key.
- conv: `copilot conv ...` resolves base_url + CONVERSATIONS_AGENT_AUTH_SECRET from store.
- coolify: `copilot coolify ...` authenticates (per ADR-002 destination).
- infisical: store gate resolves via committed adopt.config; `copilot infisical` subcommands
  per ADR-002.
Acceptance gate (mirrors Phase 4 #1): a fresh clone + NO `.env` scratch mirror resolves all of
the above; `SecretRefSource` never fail-closes at `Settings()` construction.

## Blocking owner decisions
1. Infisical store project/path for the newly-store-bound secrets (D + E): confirm
   `copilot-ecosystem / prod / /shared` (as the already-migrated secrets use) and that
   PROJECT_COPILOT_AGENT_API_SECRET_KEY / PROJECT_COPILOT_BROWSE_KEY are seeded there before
   declaring `requires_secret` (fail-closed at construction otherwise).
2. Dead keys (group G): approve dropping all 15; confirm no non-CLI tool sourcing this `.env`
   needs the 4 NON-EMPTY dead secrets (METABASE/INSIGHTS_AGENT/METHOD x2); consider rotation.
3. PROJECT_COPILOT_BROWSE_KEY classification — recommend SECRET (invariant #4).
4. DISCORD_WEBHOOK_URL (token-bearing) — currently EMPTY; approve drop now; destination if later
   used: recommend keychain (bridge resilience, matches DISCORD_BOT_TOKEN) over store.
5. ADR-002 destination for coolify token + infisical/coolify base_urls: approve loader-consults-
   ladder vs. coolify TOML/keychain bootstrap.
6. SHELL_SCRIPTS_PATH (group H) — approve drop (optional field) vs. personal/machine override;
   do NOT commit the absolute path to shared org config.

## Dependency order to "org mirror is regen-safe"
Batch 0 → Batches 1/3-secrets (parallel) → Batch 2 (needs 0) → ADR-002 (Batch 3) →
Batch 4 cutover. Removing the hand-placed symlink mirror is the LAST step and gated on the
no-`.env` scratch-mirror acceptance passing for every live service.
