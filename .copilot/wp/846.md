# ADR-010 — Production protocol journey wiring without a second router or resolver

Status: ACCEPTED FOR IMPLEMENTATION; framework-only.  
Reviewed baseline: commit `8786a93248f70a24e655b33db43af214cac62cf3`, tree `8f18219fdd7f7de95eab2cbdf9e9591e6c190cd8`.  
Prior evidence: WP-706 architecture, WP-843 implementation, WP-845 QA approval, WP-838 framework/app split.

## Context and finding

WP-843/WP-845 prove a deterministic journey evidence contract, not production integration. The real Claude path is instruction and hook driven: `.claude/commands/protocol.md` chooses the flow and agent chain; main-session `Agent` dispatch performs the invocation; `cc extensions resolve` and agent workflows discover Knowledge; `/pause` and `/continue` manipulate Task Copilot state. Today none of those boundaries emits one attributable receipt. The existing extension path also collapses a selected Knowledge contribution to a mutable filesystem path, and `/continue` finds paused tasks rather than consuming the exact next-stage capsule.

The production design is a witness/ledger around those existing authorities. It does not classify prompts, expand a flow name into a route, rank Knowledge layers, reinterpret entitlement, or choose a specialist. The existing protocol remains the sole router; the existing ecosystem/Knowledge stack remains the sole resolver. The new code accepts their decided outputs, binds them to immutable bytes, records actual dispatch, and refuses to claim integration when evidence is absent or inconsistent.

SOUL effect: “say only what you can prove” requires actual-dispatch and immutable-byte receipts. “Parse, never compute” rejects a new route classifier or a parallel Knowledge precedence engine. App files, native release/version/package/signing work, Actions, and PRD-24 are out of scope under WP-838.

## Decision

### 1. Keep WP-843 as the evidence model; add a production adapter layer

Add `tools/cc/src/cc/core/evaluation/journey_runtime.py`. It owns orchestration only and implements the existing `ProtocolRouteAdapter`, `KnowledgeAdapter`, `OperationalCapabilityAdapter`, and `ContinuationStore` seams with production dependencies. It must not contain route keyword tables, flow-to-agent maps, Knowledge rank comparisons, or raw repository scanning.

Bump the journey wire contract to `schema_version: 2.0` / `journey-adapter-v2` because mandatory security and optional operations become separate receipts. Add `SecurityReceipt(state=allowed|denied|unavailable, reason)`; restrict `CapabilityReceipt.state` to `available|unavailable|timeout|nonzero|malformed`. `denied` or `unavailable` security stops before Knowledge and dispatch. Every optional capability state preserves the core route.

`JourneyEvidence` gains `run_id`, `prompt_sha256`, and per-invocation `dispatch_sha256`. `STRUCTURALLY_INTEGRATED` is legal only when every completed specialist has both an immutable Knowledge consumption receipt and an actual dispatch receipt. A prepared-but-not-dispatched envelope is never completion evidence.

### 2. The existing protocol emits its own trace; cc only validates and records it

Add `tools/cc/src/cc/commands/journey.py` and register a `journey` Typer group in `tools/cc/src/cc/main.py`:

- `cc journey begin --task N --runtime claude --classification VALUE --specialists-json JSON --events-json JSON --prompt-sha256 HEX --json`
- `cc journey prepare --run RUN --specialist ID --json`
- `cc journey inspect --run RUN --json`
- `cc journey pause --run RUN --json`
- `cc journey resume --task N [--run RUN] --json`

`begin` accepts the classification, ordered specialists, and reasoned transition/checkpoint/skip events already chosen by `.claude/commands/protocol.md`; it validates only the `RouteTrace` structural invariants. It must not accept a prompt and decide a flow, accept a flow and expand a chain, or silently synthesize missing events.

Update `.claude/commands/protocol.md` at the existing flow-selection and Agent Invocation Pattern sections. After the model chooses the existing flow/chain, it calls `begin` with that exact decision. Before each real `Agent` call, it calls `prepare` for the exact next specialist and includes the returned opaque `invocation_marker` plus returned `knowledge_payload` in the Agent tool prompt. Checkpoint and skip reasons come from the same protocol branch that made the decision, not from cc inference.

Update `.claude/commands/continue.md` to call `cc journey resume --task N --json` before its generic paused-task behavior. When a current journey exists, it must dispatch only the returned `next_specialist` with the returned invocation marker; a completed journey returns stored completion evidence and performs no dispatch. Generic non-journey tasks keep the existing continuation path. Update `.claude/commands/pause.md` to call `cc journey pause --run RUN --json` for an active journey before setting generic paused state.

### 3. Bind the trace to the actual Agent tool call in the existing hook dispatcher

Extend the existing `.claude/hooks/pretool-check.sh`; do not add another hook dispatcher. Add `rule_journey_dispatch` immediately after the QA gate and before extension/safety rules. For a main-session framework `Agent` call carrying an `invocation_marker`, invoke the journey runtime verifier with the hook’s real `session_id`, `subagent_type`, and a SHA-256 of the exact Agent prompt. It atomically records one dispatch receipt and rejects wrong specialist, stale marker, altered payload, repeated stage, route-order drift, or missing mandatory Knowledge.

Once a session has an active journey, a direct framework `Agent` dispatch without its next marker is denied with a recovery command; this is how actual invocation, rather than model self-report, becomes evidence. Calls with no active journey retain current behavior so question-only and legacy/direct workflows do not brick. Do not parse the natural-language protocol declaration in the hook.

Increment `.claude/hooks/PROTOCOL_VERSION` and the vendored shim compatibility range only if the hook calling convention changes. If the event contract remains `pretool-check` plus stdin, leave the shim protocol at 1; adding an internal rule alone is not wire-version skew.

### 4. Extend the existing signed Knowledge authority; do not create a new precedence resolver

Refactor `tools/cc/src/cc/core/ecosystem/policy.py` to expose one verified signed-release object (repository identity, annotated-tag object/commit, root tree, ref, signer) and safe `read_blob(relative_path)` from Git object bytes. Reuse the current `verify_git_item_provenance` signature/trust/immutable-tag logic; do not reimplement Git verification in evaluation code.

Extend `tools/cc/src/cc/core/ecosystem/knowledge_skill_source.py` with an `AuthenticatedKnowledgeContribution`/receipt projection for already-resolved Knowledge sources. It returns: `layer`, `role/unit`, `repository`, `ref`, `tree`, `signer`, `contribution`, `content_sha256`, exact UTF-8 content, runtime, and adapter version. It must run under the existing entitlement binding leases and revalidate immediately before dispatch. Required production evidence rejects the current unsigned `None` compatibility source; that compatibility may continue for ordinary `cc skill` use but cannot earn a journey consumption receipt.

Modify `tools/cc/src/cc/core/extensions_resolver.py`, not a new resolver. `ExtensionResolution` gains an immutable `contributions` tuple and composed-content digest. `_load_manifest` reads `knowledge-manifest.json` from the already-authenticated signed release object for protected/signed layers; extension and required-skill bytes are read from the same pinned release identity. Existing configured-repo order remains the only personal/department/org precedence rule. `compose_agent_content` returns a typed composition object (content plus receipts), with a temporary compatibility wrapper for existing string callers.

Modify `tools/cc/src/cc/core/skill_store.py`, `tools/cc/src/cc/commands/skill.py`, and `tools/cc/src/cc/api.py` so retrieval can return the immutable receipt alongside content (`cc skill get NAME --json`). Do not expose only a path for signed Knowledge. The journey runtime consumes this existing resolved metadata; it does not walk `$CC_KNOWLEDGE_REPOS` itself.

`prepare` composes the specialist’s actual extension/required-skill payload once, computes the composed digest, stores the envelope, and returns the exact bytes to place in the Agent prompt. The hook compares the marker’s digest with the exact tool prompt payload and only then marks the specialist invoked. Missing, malformed, unentitled, unsigned, changed, or unpinned required Knowledge yields `INVALID` with no dispatch.

### 5. Optional operational capability is a narrow read-only adapter

In `journey_runtime.py`, add `CliCopilotHealthCapabilityAdapter`. It resolves `copilot` through the existing `cc.core.executables.resolve_executable("copilot")` and runs only the closed argv `[absolute_copilot, "--json", "health"]`, with bounded timeout, captured output, no shell, no credentials, and no writes. Normalize exit 0 + exact supported JSON to `available`; absent binary to `unavailable`; timeout to `timeout`; nonzero to `nonzero`; bad JSON/schema to `malformed`. Store only bounded diagnostic metadata/digest, never secret-bearing raw output.

This adapter is optional and fail-open. Mandatory security remains the existing hook/security gate and the new separate `SecurityReceipt`; an operational adapter can never manufacture `allowed` or return `security-denied`. No arbitrary command, MCP/provider, repository mutation, or network capability registry is introduced.

### 6. Task Copilot is the durable continuation authority

Keep `TcContinuationStore` in `journey.py`, but add production discovery and an inter-process lock keyed by `(task_id, capsule_sha256)` around completion lookup/store. Bind lazily to public `tc.api.store_wp/get_wp/list_wps` in `journey_runtime.py`; if Task Copilot is unavailable, production pause/resume fails closed rather than using `_local_completions`.

The capsule stores canonical route, prompt hash, immutable invocation receipts, completed prefix, exact next specialist, security/capability receipts, and adapter/schema versions. `resume --task` scans only typed `evidence` work products with the journey title/version, requires one active capsule (or an explicit `--run`), revalidates the current protocol trace and all source/entitlement identities, and returns the exact next envelope. A second fresh-process resume after completion returns the stored completion receipt without another Knowledge read, Agent dispatch, or work product. Corrupt, ambiguous, replayed-before-completion, route-drifted, source-drifted, or duplicate evidence is `INVALID`, never reconstructed optimistically.

Do not overload the generic `tc handoff` log as a continuation capsule and do not put full content in task metadata. Work products remain the evidence authority; task status/metadata may hold only the opaque run locator for discoverability.

## Verification plan / fitness functions

1. Unit: RouteTrace accepts only explicit complete event streams; no API accepts prompt-only classification or flow-name route expansion. Static test rejects route keyword/flow maps in `journey_runtime.py`.
2. Hook integration: feed real PreToolUse Agent JSON; correct marker records one actual dispatch, wrong/missing/altered/replayed marker denies, non-journey legacy dispatch remains unchanged.
3. Signed Knowledge: signed org + department fixtures prove configured-order winner receipts, exact ref/tree/signer/blob digest, checkout mutation immunity, wrong origin/tag/signer/ignored addition rejection, and entitlement revoke-between-prepare-and-dispatch rejection.
4. Consumption: actual prepared Agent prompt bytes hash to the stored composition and source receipts; a path-only or model-stated claim cannot pass.
5. Optional capability matrix: available/unavailable/timeout/nonzero/malformed all preserve the core route; command argv is exact/absolute/no-shell and raw output is not persisted. Mandatory denied/unavailable security performs zero Knowledge and zero Agent calls.
6. Continuation: isolated real SQLite `tc` store, fresh process, exact-next-stage resume, repeated completed resume idempotence, concurrent two-process completion race produces one completion work product, corrupt/ambiguous capsule fails closed.
7. End-to-end local production harness: invoke `cc journey begin -> prepare -> existing pretool hook with Agent payload -> pause -> fresh cc journey resume -> next hook dispatch` and assert route, receipts, tc artifacts, and no duplicate stage. This is structural proof, not model-quality proof.
8. Live signed proof (after TASK-297): run one owner-approved synthetic prompt through the actual `.claude/commands/protocol.md` path using published immutable organization/accounting pins; preserve only content digests and approved non-secret provenance. Both source release identities must match TASK-297. No real operational mutation.
9. Regression: focused tests above plus full `tools/cc` suite, hook harnesses, `compileall`, `git diff --check`, and independent QA/security work products bound to the reviewed commit/tree.

## Failure modes

- Model omits trace or marker: deny the journey dispatch; report missing evidence.
- Protocol changes after pause: invalid; require a new run, never remap stages.
- Source/entitlement changes between prepare and dispatch: invalid; no Agent invocation.
- Optional CLI absent/broken: typed limitation; route continues.
- Security gate unavailable or denies: fail closed before Knowledge.
- Multiple active capsules or duplicate completions: invalid and inspectable; never pick newest.
- Hook/global framework unavailable: preserve current shim security policy; a journey cannot claim completion without a dispatch receipt.
- Codex: remain explicitly `UNSUPPORTED` until a real Codex invocation interception and layered-Knowledge receipt path exists. Do not simulate parity in Claude code.

## Alternatives rejected

- A new Python keyword classifier or flow-to-chain table: second router that can drift from `protocol.md`.
- A journey-specific Knowledge walker/rank comparator: second resolver and entitlement bypass risk.
- Model transcript/self-report as consumption proof: cannot bind bytes or actual invocation.
- PreTool hook inferring route from agent sequence: records effects but fabricates classification/checkpoint/skip intent.
- Mutable path receipts: selected path can change after resolution.
- Generic arbitrary-command operational adapter: expands authority and may mutate external systems.
- Generic `/continue` paused-task scan as exact continuation: cannot guarantee exact next stage or no duplicate execution.
- App-mediated execution or evidence: violates WP-838 scope split and adds a second source of truth.
