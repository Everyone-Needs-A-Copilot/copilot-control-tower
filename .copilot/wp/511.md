# Phase 9.2 Claude proposal security contract

## Decision

Claude is an untrusted proposal generator, never a project actor and never a planner/executor. Do not extend `ProjectIntegrationLauncher.open()` to consume output. The app may request and render Python-authored proposal state, but the signed `cc` helper must own assistant invocation, artifact storage, validation, fresh inspection, plan issuance, apply, verification, rollback, and recovery.

The only acceptable model contribution is selection among opaque, freshly offered safe option IDs (or `needs-owner`). A Claude artifact must never contain or authorize a shell command, patch, file path, target, file content, URL, source path, operation payload, verification claim, or free-form rationale shown to the person. Python turns a valid option selection into the existing closed `RecipeOperationKind` plan; if no deterministic safe option exists, the project remains held/owner-decision.

## Assets, actors, and trust boundaries

Assets: human-owned project bytes including dirty work; approved-root authority; Claude credentials; machine configuration and framework sources; content-free inspection dossier; proposal/session artifacts; one-use reviewed plan capability; transaction journals/snapshots/receipts; app/helper signing and release provenance.

Actors: the person; signed Control Tower; signed `cc`; Terminal shell; installed Claude CLI; remote model/provider; adversarial project content/filenames/Git metadata; accidental or malicious same-UID processes.

Boundaries:
1. App -> `cc`: versioned JSON only; app never constructs proposal paths or operations.
2. `cc` -> Claude: bounded content-free dossier over stdin, in a private non-project cwd.
3. Claude -> `cc`: hostile bounded stdout, not an instruction channel.
4. Private proposal store: untrusted result vs Python-normalized accepted proposal.
5. Accepted proposal -> fresh reconciliation plan: exact inspection/request/option binding.
6. Plan -> project: existing lock, identity, allowlist, snapshots, journal, rollback, verification.
7. Source -> packaged app/helper: exact-artifact Finder-shaped release proof.

## Existing controls to preserve

- Request schema 1.0 canonicalizes literal absolute paths and bounds recipe IDs.
- Python has a closed operation enum with no shell or patch operation.
- Plans bind request and fresh-plan fingerprints, expire, claim once, and are freshly recomputed before execution.
- Project execution uses approved targets, O_NOFOLLOW/openat anchoring, identity checks, locks, source/before fingerprints, fsynced journals, snapshots, compare-and-swap rollback, durable receipts, and independent verification.
- Swift request files are private 0600/same-UID under a 0700 app runtime and are unlinked after invocation.
- The current launcher shell-quotes paths and does not trust assistant self-report. Those two properties carry forward; the current launcher itself does not.

## Prioritized threats and required mitigations

### Critical — assistant can mutate/exfiltrate directly

Existing `ProjectIntegrationLauncher` runs Claude in the project cwd with normal project discovery, tools, settings, hooks, plugins, MCP, user HOME, and interactive authority. A malicious CLAUDE.md/plugin/hook or prompt can edit files, run shell, or exfiltrate secrets before Python sees output.

Required: Terminal invokes only the absolute embedded `cc` plus a regex-bounded opaque session ID. `cc` launches Claude with `subprocess` argv (never shell), private cwd outside every project/root, prompt on stdin, minimal allowlisted environment, no project/additional directories, and at minimum: `--safe-mode`, `--tools ""`, `--permission-mode plan`, `--strict-mcp-config` with an empty config, `--disable-slash-commands`, `--no-session-persistence`, `--no-chrome`, `--print`, `--input-format text`, `--output-format json`, and a per-session `--json-schema`. Reject unsupported Claude versions/flags; never fall back to interactive/direct-project mode. `--bare` is not a default substitute because current help says it disables OAuth/keychain reads and requires API-key-style auth.

### Critical — prompt/argv injection and arbitrary execution

The current launcher turns prompt bytes into one argv token through command substitution. Shell quoting prevents shell metacharacter execution, but a prompt beginning with an option-like token can still alter assistant CLI parsing. Consuming a result would add a second injection boundary.

Required: prompt only on stdin; no prompt/project/result path in Terminal command. Proposal schema `additionalProperties=false`; dynamic enum contains only option IDs offered by the bound inspection. No command/patch/content/path fields. Python JSON parser rejects duplicate keys, NaN/Infinity, invalid UTF-8/control characters, excessive depth/count/string length, and payloads over a small fixed maximum (recommend 64 KiB). Provider-side `--json-schema` is defense-in-depth; Python revalidates independently.

### Critical — prompt injection from project evidence

Project instructions, filenames, branch names, remotes, and metadata are hostile. Delimiters/system prompts cannot make them trustworthy.

Required: reuse the current content-free dossier approach: counts, typed evidence IDs/states, preservation entries, missing requirements, allowed option IDs, fingerprints, and stop conditions only. Never send file bodies, `.env`, Git remote credentials, hooks, assistant configuration, raw errors, or arbitrary filenames when opaque evidence IDs suffice. A malicious output can at worst choose an offered safe ID; Python may still reject it after reinspection.

### High — stale/dirty/wrong project authority

A proposal can outlive HEAD/index/worktree/config/source changes, or be replayed for another path. Dirty trees contain human work and must not be made a model-owned merge problem.

Required: bind session and normalized proposal to schema version, random session nonce, canonical request fingerprint, inspection ID, canonical project identity (device/inode/Git identity), selected components, offered option set/fingerprint, helper/framework versions, creation/expiry, and raw-result digest. Re-inspect at result acceptance, plan issuance, and existing apply preflight. Any HEAD/index/worktree/untracked/conflicted/detached/config/source/identity change yields `stale`/`held`, no plan. Proposal generation is read-only; all dirty trees remain unchanged and non-applicable.

### High — path traversal, symlink/hardlink, and filesystem races

Required: callers pass session IDs, never proposal/result paths. Resolve all artifacts beneath a private machine-state root. Create/descend with directory fds plus O_DIRECTORY/O_NOFOLLOW; files O_CREAT|O_EXCL|O_NOFOLLOW 0600; fstat regular, same UID, nlink==1, no group/world bits; directory 0700 and same UID. Reject traversal/control/Unicode-confusable session IDs. Hold project fd/identity through critical checks. Reject project-root/ancestor/target symlink swaps and aliases outside approved roots.

### High — tampered/replayed proposal/result/state

Required state machine: `prepared -> running -> captured -> accepted|rejected|interrupted -> planned|consumed`. Atomically/fsync every transition. Store raw result as quarantined untrusted evidence and a separate canonical Python-normalized proposal with SHA-256; never let the app read files directly. One active lease per session/project/inspection, one accepted result, one plan issuance, one claim. A retry receives a new attempt ID and never silently reuses partial output. Tampered state/result/proposal/plan or replay after consumption fails closed.

### High — secrets and social engineering

Required: no automatic pasteboard copy; no prompts/results in argv, process listings, shell history, analytics, ordinary logs, diagnostics, or UI. Minimal environment excludes tokens, SSH/Git variables, proxy credentials, debug variables, and arbitrary HOME/project settings; provide only what approved Claude auth needs. Use canary-based redaction tests. Do not render raw Claude prose/rationale: it can contain instructions to the person. UI summaries and next actions remain Python-authored.

### High — interruption, retry, idempotence, rollback

Generation has zero project writes, so interruption cleanup concerns private artifacts only. `cc` owns the Claude child process group, timeout/cancel, bounded stdout/stderr, exit/signal, and final durable state. On app/Terminal death, recovery recognizes a dead lease and marks the attempt interrupted; no auto-rerun (cost and duplicate-result risk). Explicit retry creates a new attempt. Proposal recovery never runs recipes. Once a reviewed plan exists, reuse the existing apply claim/journal/snapshot/rollback/recover path; recovery never executes recipe code anew.

### Medium — assistant absence/failure/resource abuse

Not found, non-executable, incompatible version, auth failure, exit 1/2, signal, timeout, empty/truncated/malformed output, output-after-nonzero, or oversized stdout all become typed blocked/interrupted results. Keep only bounded/redacted stderr. No clipboard/direct-project fallback and no false “nothing changed” unless the proposal/apply ledgers prove it. Bound model budget, wall time, output bytes, and explicit retries.

### Medium — release drift

Helper notarization evidence must record a Finder-shaped proposal probe. The Control Tower release gate must execute the exact embedded helper with an inert local fake `claude`, malicious content-free fixture, schema validation, proposal normalization, stale/tamper/refusal/retry/recovery checks, and project-tree digest stability before app notarization. A signed app headless seam must prove bundle-relative helper use; DMG-mounted app must match.

## Claude CLI evidence

Installed `claude 2.1.221` help documents the required print, safe-mode, no-tools, permission, strict MCP, no-session-persistence, no-Chrome, JSON output, and JSON Schema flags. It also warns that non-interactive mode skips workspace trust and silently ignores invalid settings, reinforcing the private-cwd/safe-mode/strict-validation requirement. Live Docs retrieval returned unusable HTML, so the local installed help is the primary observed compatibility evidence; implementation must pin/test a minimum supported version rather than assume future flags.

## Residual risk

The remote model can choose a wrong but offered safe option and the provider necessarily receives the bounded dossier. Review, deterministic Python translation, stale-plan refusal, rollback, and independent verification reduce impact but cannot prove model quality. A fully compromised same-UID account can attack user files/private state outside this product's defensible boundary. Admin-managed Claude policy may still exist under safe mode; empty tools/private cwd/strict MCP must remain the structural containment. No proposal path should ship if any model-authored byte can directly reach project mutation or person-facing instructions.
