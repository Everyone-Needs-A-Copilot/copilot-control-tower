## ADR-006: The setup transaction is a preflighted saga with a proven history classifier

**Status:** Proposed (supersedes nothing in ADR-005; extends its clause 6 and clause 9)

**Context.** Control Tower 0.2.4's first live apply on ENAC's Mac stopped on `cli-copilot` after already creating two Personal GitHub repositories, while telling the owner setup stopped "before changing anything". Three forces collide. First, `cc onboard` classifies repository history without proving the ancestry condition its own apply enforces (`onboard.py:803-805` sets `action=repair` and the detail "a clean fast-forward is available" from nothing more than `HEAD != remote_sha`). Second, the apply performs irreversible GitHub writes (`onboard.py:2330`, personal stage) before the deterministic local preconditions it will later fail on (`onboard.py:2375`, visible-repositories stage). Third, cross-system atomicity across GitHub and local Git does not exist, so "transaction" was aspirational language over an unrecorded sequence of writes. The app cannot fix any of this: under invariant 1 it parses and renders, it does not compute repository state.

**Decision.** Three coupled changes, all in `cc`, with the app changing only its rendering.

1. A closed history classifier replaces the boolean behind-check. Its states are exact, fast-forwardable, dirty, ahead-only, divergent-identical-tree, divergent-different-content, wrong-origin, unreadable. Only `fast-forwardable` — proven by `git merge-base --is-ancestor HEAD <target>` — may be labelled a safe fast-forward and may be auto-acted on. `ahead-only` and both divergent states route to the owner; `dirty` is preserved untouched as today.
2. Every deterministic preflight, including the classifier, runs before the first irreversible remote write. The ordered transaction's remaining actions must not be able to fail for an already-knowable reason.
3. What remains genuinely non-atomic becomes a recorded saga. The report carries a `completed_actions` ledger; a blocked apply after any write reports exactly what was created, what remains, and the safe next actor. "Nothing changed" becomes a claim the emitter can only make when the ledger is empty.

**Consequences.** Easier: the plan screen becomes a promise the apply can keep, so the owner can review a read-only sixteen-row plan and trust it; recovery becomes resumable rather than a retry-and-pray; the false-success path in `--ff-only` (below) disappears. Harder: `cc onboard` grows a real state machine and a persisted ledger, which is more code and more test surface; the classifier's non-fast-forward states need human-legible copy that never dumps a Git error at a non-technical person, which is design work in the Quiet Instrument voice; and three of the sixteen live rows will now correctly refuse to auto-repair, so the owner must resolve `cli-copilot`, `cli-copilot-internal` and `codex-copilot` by hand before the topology can reach 16.

**Alternatives rejected.** Two-phase commit across GitHub and local Git — GitHub exposes no prepare/abort, so this would be a lie in a different shape. Compensating deletion of created Personal repositories — deleting a repository a person may already have pushed to violates never-destroy and trades a truthful partial state for a destructive one. Classifying history in the app from `git status` output — violates invariant 1 and would create the second brain SOUL.md forbids. Treating the identical-tree divergence as equivalent and silently accepting the local branch — the trees match today but nothing guarantees they match at the next tag, so it re-creates the same false promise one release later.

## ADR-007: The `layers` array is a load-bearing contract field, not an optional convenience

**Status:** Proposed

**Context.** The phase-6 handoff recorded that the signed helper returned an empty `layers` array while source returned 16 rows, and attributed it to PyInstaller import inputs. That does not reproduce: the exact installed binary (cc 1.7.16) returns 16 fully-populated rows today. The actual mechanism is that `layers` is state-dependent by construction. `_ecosystem_result` (`onboard.py:1907`) initialises `report["layers"] = []` and copies each topology field only `if key in layer` (`onboard.py:1928`); the call site at `onboard.py:2134` omits `layers` entirely, and those at 2341, 2361, 2402 and 2453 pass raw `manifest["layers"]`, which carry none of the topology fields. So one binary legitimately emits 16 populated rows, 16 skeletal four-field rows, or zero rows depending on which branch it exits through. `onboard.schema.json` validates all three: `ecosystemLayer.required` is `[id, product, role, rank]`, every topology field is optional, and `layers` has no `minItems`.

**Decision.** The schema encodes what the UI depends on. `layers` gains `minItems` matching the expected roster size for the transaction, and `ecosystemLayer` requires `action`, `local_state`, `sync_state`, `remote_state`, `repository_name` and `local_path`. Every ecosystem exit path in `cc` emits fully-populated topology rows or an explicit typed absence, never a silently-degraded array. The release gate executes the exact packaged binary against a deterministic fixture and asserts the row count and per-state actions.

**Consequences.** Easier: the app can render the inventory without defensive branching, and a regression of this class fails the gate rather than the owner's live run. Harder: tightening `required` is a breaking schema change, so it needs a version bump and a coordinated helper/app release; and every early-return branch in `build_ecosystem_onboard_report` must now carry topology rows, which means computing them earlier than some blocked paths currently do.

**Alternatives rejected.** Rebuilding the PyInstaller packaging inputs — would have consumed the phase and fixed nothing, since the binary is correct. Making the app tolerate empty `layers` — pushes a CLI contract defect into the skin and lets the silent-degradation path survive. Asserting row count only in the app — the app is not the place a CLI contract is enforced.

## Fitness functions

These are automated checks, not review items. F-1: no code path may emit `action: repair` without a passing `merge-base --is-ancestor` proof, asserted by a fixture covering all eight history states. F-2: a failpoint injected between preflight and the first remote write produces zero GitHub mutations, asserted by a recorded-call fixture. F-3: a failpoint injected after a remote write produces a non-empty `completed_actions` ledger and no "nothing changed" string in the rendered result. F-4: the exact packaged binary returns `len(layers) == expected_roster` for the deterministic fixture, and its normalized report equals the source helper's. F-5: after any apply that claims a row synced, `HEAD == target SHA` for that checkout.
