# Adversarial acceptance matrix — TASK-296 production protocol wiring

Scope: framework-only production wiring from ADR-010 (WP-846), using secure deterministic contract commit `dfaafbe0ddaaa668cdcf8858478784f73a7becbe` / tree `b244ff54d21c67061953348b7005ec1713a85b60`. No app, release, signing, Actions, content-repository, provider, or external mutation.

## Evidence baseline and current seams

ARTIFACT: file-check | reviewed WP-846, WP-855, WP-856, WP-857 and exact `dfaafbe0` tree; inspected current `.claude/commands/protocol.md`, `.claude/commands/pause.md`, `.claude/commands/continue.md`, `.claude/hooks/pretool-check.sh`, `.claude/settings.json`, agent manifest/definitions, `extensions_resolver.py`, signed Knowledge policy/source, skill store/CLI/API, and public `tc.api`/work-product persistence.

- `dfaafbe0` changes only `core/evaluation/journey.py`, its exports, and synthetic tests. It provides verifier-issued Knowledge receipts, mandatory-security separation, digest-only disclosure, row identity checks, and a host file lock, but has no real protocol/CLI/hook/resolver/Agent dispatch integration. It is the secure contract baseline, not AC-22 production proof.
- `protocol.md` is currently the sole human/model router. It owns keyword flow selection, ordered chains, checkpoint/skip choices, and direct `@agent-X` invocation instructions. Production code must witness its explicit decision; no Python prompt classifier or flow-to-chain expansion is permitted.
- `pretool-check.sh` is already the single PreToolUse dispatcher. Actual payload facts available are top-level `session_id`, `tool_name`, `agent_type`, plus `tool_input.subagent_type` and the exact Agent prompt. Current rule order is force-delegate -> QA gate -> extension resolution -> destructive command -> path scope. Its global error traps fail open, and extension resolution can only allow/deny; it cannot rewrite a prompt.
- `extensions_resolver.py` is the existing precedence authority but currently reads `knowledge-manifest.json` and extension files from mutable filesystem paths, returns a path-only `ExtensionResolution`, and `compose_agent_content()` rereads that path. Signed Knowledge skill reads separately use `verify_git_item_provenance`, immutable tree snapshots, and entitlement binding leases. Production wiring must extend and converge these authorities, not walk repos again.
- `cc skill get` currently prints plain content and has no `--json`; `cc.api.skill_get()` returns path plus content but no immutable receipt.
- Public Task Copilot signatures are `store_wp(task_id=, type_=, title=, ...)`, `get_wp(wp_id=)`, and `list_wps(task=, type_=, ...)`. SQLite uses WAL and a busy timeout, but `work_products` has no uniqueness key on journey title/digest and the public transaction helper does not itself issue `BEGIN IMMEDIATE`. Cross-process exactly-once behavior therefore cannot depend on a check-then-insert sequence.

## Claim boundary

A passing result may claim: the existing Claude protocol supplied an explicit route; mandatory security allowed it; immutable, signed and entitled Knowledge bytes were placed in the exact Agent tool prompt; the existing PreToolUse dispatcher observed and authorized that exact dispatch once; and Task Copilot preserved an exact continuation capsule.

A PreToolUse receipt is evidence that an Agent call was intercepted and authorized before execution. It is not evidence that the subagent successfully completed or that its output was correct. Without a correlated post-execution lifecycle receipt, persisted fields and documentation must say `dispatch_observed`/`dispatch_authorized`, not `specialist_completed`. Model quality remains out of scope. Codex remains `UNSUPPORTED`.

## Required harnesses and proof artifacts

1. Unit/property tests: v2 evidence invariants, opaque marker binding, canonical composition, typed errors, disclosure allowlists, and static no-second-router/no-second-resolver fitness functions.
2. Hook integration harness: real stdin JSON matching Claude PreToolUse shape and actual dispatcher order. It must cover D-02 through D-12 and use isolated state directories. Assert exit code, deny JSON, stderr sanitation, and persisted receipt bytes.
3. Signed Git fixture: annotated tags signed by test keys admitted only through injected test trust, two Knowledge layers, mutable checkout attacks, tag movement, wrong origin/signer/ref, ignored additions, and lease revocation. No production trust root is modified.
4. Real isolated tc SQLite integration: public `tc.api.store_wp/get_wp/list_wps`, file-backed large WPs, fresh processes, ambiguous/corrupt rows, and C-01 through C-09. Do not substitute the in-memory `Rows` fake for production claims.
5. End-to-end local Claude production harness: protocol-supplied `begin -> prepare -> real pretool-check Agent JSON -> inspect/pause -> fresh-process resume -> next prepare/hook`, proving actual dispatch receipt consumption and no duplicate stage. This is structural dispatch proof only.
6. Live signed proof remains gated by TASK-297: one owner-approved synthetic prompt through the actual protocol command path with published immutable organization/accounting pins. Preserve only approved provenance/digests; no operational mutation.
7. Regression: focused journey/runtime/resolver/Knowledge/skill/main/hook tests, full `tools/cc` suite, all hook harnesses, Ruff, compileall, and `git diff --check`. Independent QA and security must bind commit and tree.
