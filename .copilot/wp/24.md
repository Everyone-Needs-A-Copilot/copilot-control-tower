# M4 Architecture — Distribution, Signing & Self-Update (WS-D)

Scope: the machinery behind `CliStatus::{UpdateAvailable,UpdatingApp}` (already rendered by M1).
Parse-never-compute holds: self-update/signing/watchdog are OS-integration + distribution, not
ecosystem-state computation. Trade-off frame per decision: *what quality we optimize / what we
sacrifice / is it reversible*.

## Fitness functions (CI-enforced; live in Stream-Z as `tests/fitness_*.rs` + a plist lint)

- **FF-M4-1 `KeepAlive` is never `true`.** Lint the watchdog plist: `KeepAlive` must be a dict
  containing exactly `SuccessfulExit=false`; a bare `<true/>` or `RunAtLoad=true` fails the build.
- **FF-M4-2 No bypass flags.** grep-deny `--force` / `--skip-verify` anywhere in `src-tauri/src`
  and `dist/`. The verifier exposes no "insecure" branch.
- **FF-M4-3 Trust root is code, not config.** The minisign pubkey + default feed are `const`s in a
  compiled module; a fitness test asserts no code path reads them from a preference/env/file.
- **FF-M4-4 Feed/security keys are forced-domain-only.** `UpdateFeedURL`/`AllowSelfUpdate`/
  `UpdateChannel` are read solely via the `settings::managed` forced-domain reader; a fitness test
  asserts no user-domain / env / arg read path exists for them.
- **FF-M4-5 Fail-closed verify.** A malformed/missing signature or unstapled bundle → `Reject`,
  never `Promote`. Absence is refusal, mirroring M1's fail-closed doctor parse.
- **FF-M4-6 No-heartbeat ⇒ rollback.** The rollback state machine, given no heartbeat within the
  launch window, must reach `RolledBack{poisoned}` and never `Promoted`.
- **FF-M4-7 Single process.** No second long-lived app process is spawned; the watchdog is launchd.

## ADR-M4-001: Crash-only launchd watchdog (`KeepAlive={SuccessfulExit:false}`)
**Status:** Accepted (ratified Case Law — SOUL.md line 147/408).
**Context:** The app must "stay on" but must never resurrect a build that crashes on launch.
`KeepAlive=true` restarts unconditionally → a bad build crash-loops and fights an intentional Quit.
**Decision:** LaunchAgent with `KeepAlive={SuccessfulExit:false}`, `RunAtLoad=false`, a
`ThrottleInterval`, plus an app-level launch-failure circuit breaker (N non-zero exits in a window →
stop relaunching, surface "reinstall"). `SMAppService` owns launch-at-login (one mechanism).
**Consequences:** Easier — clean Quit stays quit; a crash relaunches; a crash storm self-limits.
Harder — a *hang* (no non-zero exit) needs its own liveness heartbeat, not launchd's trigger (ties
to ADR-004). **Reversible:** yes (plist swap).
**Alternatives rejected:** `KeepAlive=true` (OUT — resurrects bad builds); a second daemon/in-app
fallback loop (OUT — single-process invariant #2, was a concrete `copilot.lock` prune race).

## ADR-M4-002: Rollback lives in the stable watchdog, not the new bundle
**Status:** Accepted.
**Context:** A bundle that crashes on launch cannot be trusted to roll *itself* back.
**Decision:** A tiny **stable watchdog binary, never self-updated**, stages the new bundle, launches
it `--self-test`, and waits for an early liveness **heartbeat file** (path/schema frozen in S1). No
heartbeat within the launch attempt → discard staged bundle, keep last-known-good, mark version
**poisoned** (that channel never re-serves it), notify. Staple is verified **offline** before promote.
**Consequences:** Easier — a bad self-update auto-reverts with zero user action; air-gapped fleets are
safe (offline staple check, no notarization-CDN dependency at swap). Harder — a second tiny binary to
sign + keep stable; the heartbeat contract is now load-bearing. **Reversible:** the *mechanism* is,
each rollback event is the safe direction by construction.
**Alternatives rejected:** in-bundle self-rollback (OUT — trapped in the thing that won't start);
"just reinstall" as the only recovery (worse UX; MDM force-push `.pkg` remains the floor guarantee).

## ADR-M4-003: Compiled-in trust root; feed/keys forced-domain-only
**Status:** Accepted (Case Law — SOUL.md line 409).
**Context:** If the update feed or signing pubkey can be repointed by a user-writable preference, a
preference-write is remote code execution.
**Decision:** The minisign update-signing pubkey and the default `UpdateFeedURL` are **compiled-in
constants**. `UpdateFeedURL`/`FoundationMirror`/`AllowSelfUpdate`/`UpdateChannel` are honored **only**
via `CFPreferencesAppValueIsForced`; a user-domain-only value is ignored in favor of the compiled-in
default and logged as a tamper event. Minisign key is independent of the Apple codesign chain
(separate custody), targeting two-of-N signing.
**Consequences:** Easier — no supply-chain preference-write attack; unmanaged machines still have an
authoritative trust root. Harder — power users cannot point at a local mirror (intended: SOUL.md
Drift §; that convenience is the attack). **Reversible:** trust-root rotation is a code release, by design.
**Alternatives rejected:** reading `UpdateFeedURL` from the user domain "so power users can use a
mirror" (OUT — supply-chain RCE); trust root as config (OUT — trust roots are code).

## ADR-M4-004: Update state machine (parse the doctor signal, own the transport)
**Status:** Accepted.
**Context:** M1 already parses `doctor --json` → `UpdateAvailable`/`UpdatingApp`. M4 must not
re-derive that verdict; it owns only the *transport* (download/verify/stage/promote/rollback).
**Decision:** State machine: `Idle → CheckedAvailable(compat-gated) → Downloaded → Verified(sig+staple,
fail-closed) → Staged → SelfTesting(--self-test, heartbeat wait) → {Promoted | RolledBack{poisoned}}`.
The "should we update" trigger is the parsed doctor/compat signal (never an app-computed health score);
`Verified`→`Staged` refuses on any verify failure. Bidirectional `min_schema`/`max_schema` compat gate:
a newer CLI *pulls* a newer app; the app refuses to drive an out-of-range CLI ("versions don't match —
click to update").
**Consequences:** Easier — clear seam between "CLI decides state" (parse) and "app moves bytes safely"
(own). Harder — two version surfaces (app semver + schema_version) to reconcile in the compat matrix.
**Reversible:** yes.
**Alternatives rejected:** app-side "is an update needed" health computation (OUT — invariant #1);
unidirectional (newer-only) compat gate (OUT — an older CLI is as fatal as a newer one, B-H6).

## ADR-M4-005: Vendored CLI — one owner, verify-not-resign, pinned SHA
**Status:** Accepted (fixes B-C4, A-C2, B-H1, B-M5).
**Context:** Two repos, one signature requirement; a compat-matrix deadlock if both self-update.
**Decision:** Control Tower is the **single owner** of the vendored `cc`; `COPILOT_MANAGED_BY=controltower`
disables `cc self-update`. `claude-copilot` CI publishes `cc` already-signed/notarized/universal at a
pinned SHA+version; Control Tower CI **verifies** (`codesign`/`spctl`), **never re-signs**, and **blocks
release if the vendored `cc` < compat floor**. `.pkg` postinstall strips quarantine; a `cli-spawnable`
doctor check surfaces a Gatekeeper kill as a named finding. Vendoring is wired via `tauri.conf.json`
`bundle.resources` into `Contents/Resources/cc` (the path M1 already resolves), **not** `build.rs`
(keeps `build.rs` Stream-A-owned; avoids A↔D file conflict).
**Consequences:** Easier — no lockstep-signing deadlock; the app drives a known-good CLI. Harder —
release is gated on the cross-repo artifact existing at the pinned SHA (D-3 carryover: real `cc` batched
for owner; M4 vendors a placeholder). **Reversible:** re-pin to a new SHA.
**Alternatives rejected:** app re-signs the CLI (OUT — two signing authorities); both binaries
self-update independently (OUT — compat deadlock).

## Owner-gated vs autonomous split
See PRD §"Owner-gated vs autonomous". Code/config/verification/tests are autonomous now; the actual
codesign/notarize/staple, minisign private key + two-of-N custody, cross-repo `cc` push + release build,
and the update-feed endpoint are owner-gated and batched.

## Gaps: D-4-M4 (update-feed endpoint undefined), D-3 (real signed cc), minisign custody, heartbeat-file
contract (defined by S1). See PRD §"Contract / infra GAPS".
