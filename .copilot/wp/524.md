# Phase 9.2 final packaged-artifact QA — Control Tower 0.6.0 / cc 2.7.0

Task: TASK-248 (P9.2-S3 — Integrated live-machine and security verification). This is an independent re-verification of the packaged artifacts already reported as shipped; every command below was executed fresh in this session against the live filesystem, the installed app in /Applications, and the git remote — none of the numbers are restated from the handoff without a command backing them.

## Scope and method

I did not trust the prior evidence block as given. For each claim I ran my own command against the actual artifact (codesign/spctl/stapler against the installed .app and the released DMG, sha256 against both the vendored helper and the embedded helper, `git rev-parse`/`git merge-base` against the tag and branches, and two independent live runs of `cc reconcile assess --json` through the installed helper, diffed against each other). No live project was mutated at any point; `git status --porcelain` on a sampled project (BM) came back empty both before and after the assessment runs, confirming read-only behavior.

Arithmetic checked with `jq`, not by eye: `project_counts` minus `total` sums to 63, matching the reported `total`. `batch_summary.correction + needs_review + new_setup + ready` = 1+47+0+15 = 63, matching `batch_summary.total`. `.projects | length` = 63 and `.projects | map(.path) | unique | length` = 63 — no duplicate project paths. Grouping every project by its `.route` field gives `could-not-verify:3, customized-guided-route:16, held:26, owner-decision:1, ready:15, safe-update-available:2`, summing to 63 with each project contributing to exactly one group — this is the strongest check, since it confirms per-project singularity rather than trusting a pre-aggregated summary block. ## Observation (non-blocking)

The live machine's `machine_summary.state` is `action-required` — 4 of 16 ecosystem layers are reported behind remote (knowledge-foundation, cli/foundation, claude/claude-foundation, codex/codex-foundation) and the shared org credential store is unreachable, which fans out into per-connection blockers (uspto/crm/brevo/n8n/coolify/insights/project/conv). This is a live-machine ecosystem-freshness/credential-store condition, not a defect in the packaged 0.6.0 app or the vendored 2.7.0 helper — the assessment ran to completion and was stable across two runs despite it, which is itself evidence the packaged software degrades gracefully rather than failing. It matches a previously known condition (org credential store rejecting this machine's credentials) and is an ecosystem-owner follow-up, not a release blocker for this QA pass.
