# Scope and decision

Read-only security architecture review of the proposed remediation for WP-890: take an exclusive advisory lock on the fixed `/private/tmp` directory inode itself, after no-follow identity and ownership checks, with a bounded acquisition timeout; serialize journey state transitions globally; and validate pause history by tc row-ID chronology, generation, and the progress prefix that existed at each pause row.

VERDICT: ARCHITECTURE APPROVED-WITH-CONDITIONS

No same-user namespace-replacement bypass remains when the implementation locks the validated `/private/tmp` directory descriptor itself rather than any child pathname. The row-order rule closes the demonstrated late generation-one pause insertion if generation is derived from the dispatch rows whose IDs precede that pause, rather than trusted from the capsule. This is approval of the remediation boundary only. A new exact implementation commit still requires fresh security and QA review before TASK-296 can pass.

# macOS evidence

ARTIFACT: security-check — on this macOS host, uid 501 opened `/private/tmp` with read-only, directory, no-follow, close-on-exec flags; lstat and fstat matched device/inode; the descriptor was root-owned, directory-typed, sticky, and non-inheritable.
ARTIFACT: test-run — while that descriptor held `LOCK_EX|LOCK_NB`, an independent fresh Python process was denied with `BlockingIOError`; after release, a fresh process acquired it. A separate open in the original process was also denied while the first open held the lock.
ARTIFACT: file-check — `/private` is root-owned and not writable by ordinary users; `/private/tmp` is root-owned mode 1777. An ordinary user therefore cannot rename or recreate the directory pathname, unlike the prior same-user-owned lock anchor.

# Required lock construction

1. Use the literal absolute path `/private/tmp`, not `/tmp`, an environment-derived path, a child lock file, or a caller-selected directory. Open it with `O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC` where available.
2. Compare post-open `fstat` device/inode to `lstat('/private/tmp')`; require uid 0, directory type, and sticky bit. Recheck pathname-to-descriptor identity after acquiring the lock and before every authoritative commit. Any open, stat, identity, ownership, type, sticky-bit, or lock-support failure denies; there is no fallback to the prior anchor.
3. Acquire `LOCK_EX|LOCK_NB` using a monotonic bounded deadline. Timeout and `EWOULDBLOCK`, `ENOTSUP`, or unexpected errors fail closed with a value-suppressing diagnostic. Never wait indefinitely.
4. Keep the exact descriptor open and locked across the complete read-validate-authorize/pause/final append transaction. Reload tc state after acquisition, validate it, append, verify the exact returned row and clean guard, then release. All framework paths that mutate journey authority must use this same lock.
5. Mark the descriptor close-on-exec and do not fork while it is held. macOS flock state can be inherited through a duplicated/forked descriptor; an inherited child can prolong the lock or explicitly unlock the parent's claim. Release in a finally/defer path and close every duplicate.
6. Keep the critical section bounded. Provider/Agent execution and unrelated long-running work must not hold the global directory lock. If mutable authority inputs are resolved outside it, bind their immutable receipts and revalidate all tc-backed facts after lock acquisition.

# Required chronological pause invariant

For every pause row P, use the real positive numeric tc row ID as the cutoff and reconstruct a prefix from rows with `row.id < P.id`. Do not use list order or second-resolution timestamps.

- Derive `g` as the count of authorized dispatch rows in that prefix; require `P.generation == g`. Dispatch stages in the prefix must be exactly the contiguous set `0..g-1`, with each stage's preparation, binding, authorization, prompt, Knowledge, security, and route identities valid in row-ID order.
- Validate the capsule solely against that historical prefix and the exact allowed next-stage state at the cutoff. There must be no stage greater than `g`, and any stage-`g` preparation or binding included before P must be reproduced exactly by the capsule. Later rows must never influence this historical check.
- Pause-row IDs must increase, pause generations must strictly increase, and a generation may have at most one pause row. A later pause need not exist for every generation, but it cannot backfill an earlier generation. Duplicate, nonnumeric, nonpositive, missing, or conflicting IDs deny.
- Later legitimate progress may follow P. Each later dispatch must have a greater row ID and be validated from the resumed capsule/authority state. Terminal evidence must follow all dispatches and validate all historical pause rows using their own cutoffs.
- On append, require the returned pause row ID to be greater than every row observed inside the lock, then reread and verify the exact full row and clean guard before releasing. Tests must cover a generation-one pause appended after generation-two progress, reordered IDs, duplicate generation, pause before required dispatch, later valid progress after pause, and concurrent pause/dispatch from two fresh OS processes.

This rule rejects WP-890's concrete bypass: a late generation-one row appended after two dispatches sees two preceding dispatches, so its claimed generation one cannot equal the derived prefix generation two.

# Residual risk

- LOCAL AVAILABILITY, MEDIUM: `/private/tmp` is intentionally openable by ordinary users. The local test proves an unprivileged user can acquire the directory lock and block every cooperating journey on the Mac. The bounded timeout converts this into a fail-closed denial of service rather than an authorization bypass. Global serialization also creates contention across projects and users, and an unrelated process that locks the same directory can collide.
- ADVISORY-LOCK TRUST, DOCUMENTED: flock does not stop a process from ignoring the protocol or directly rewriting the tc database. The design continues to trust tc storage and all framework versions as cooperative authority writers. A database transaction plus a uniqueness/consumption constraint remains the stronger long-term primitive.
- PRIVILEGED ADVERSARY, OUT OF SCOPE: root can rename, remount, replace, or bypass `/private/tmp`. The proposed checks protect against ordinary same-user namespace manipulation, not a compromised administrator or kernel.
- PROCESS LIFECYCLE, LOW: forked descriptor inheritance can extend or release the claim unexpectedly; close-on-exec alone does not protect a raw fork. The implementation and regression suite must enforce the no-fork critical section.
- PLATFORM AVAILABILITY, LOW: if directory flock becomes unsupported in a sandbox or future runtime, the path must deny instead of silently weakening to a replaceable file lock.
- ROW-STORE TRUST, DOCUMENTED: tc row IDs provide chronology only while the append-only database is trusted. An actor able to delete/rewrite complete rows, IDs, guards, and hashes can forge history; cryptographic append-only provenance is not introduced by this remediation.

# Required verification before acceptance

Use real tc and fresh OS processes to prove mutual exclusion, bounded timeout, crash release, fork/descriptor handling, and exactly one authority consumption. Add deterministic identity failures for symlink, wrong owner/type/sticky bit, lstat/fstat mismatch, and unsupported-lock behavior without modifying the real directory. Exercise all chronological negatives above and the valid multi-generation resume/terminal path. Re-run the complete journey, runtime, entitlement, Knowledge, hook, disclosure, guard, and multiprocess suites against the exact implementation commit/tree.
