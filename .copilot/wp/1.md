# Milestone 1 Architecture — Tray + Doctor Timer + Product-First Dropdown

Thin-skin (parse-never-compute) face over `cc doctor --json`. This document is the buildable design:
project layout, the Rust parse boundary, the CLI-spawn design, the mock-fixture strategy, and the ADRs.

---

## 1. Tauri v2 project layout

```
copilot-control-tower/
  src-tauri/                         # the Rust core (the whole supervisor lives here)
    Cargo.toml
    tauri.conf.json                  # ActivationPolicy::Accessory (LSUIElement); no dock icon;
                                     #   single instance; window hidden by default (popover-only)
    build.rs
    icons/                           # aviator template masks + badge-shape overlays (PDF/PNG @1x/@2x)
    src/
      main.rs                        # entrypoint: build tray, start doctor timer, register commands
      lib.rs                         # app wiring, Tauri Builder, managed state handle
      cli/
        mod.rs
        path.rs                      # ABSOLUTE, translocation-safe cc-path resolution (+ dev override)
        spawn.rs                     # spawn `cc doctor --json`, exit-code 0/1/2, timeout, stderr capture
      model/
        mod.rs
        doctor.rs                    # serde structs mirroring doctor.schema.json (raw wire types)
        envelope.rs                  # schema_version type + bidirectional range-gate
        state.rs                     # the TYPED, fail-closed domain state the UI renders (TrayState,
                                     #   ProductView, LayerView, StatusState enum incl. CliUnreadable)
        failclosed.rs                # the fail-closed deserialization defaults (missing => worst)
      render/
        mod.rs
        glyph.rs                     # StatusState -> tray template image + badge overlay (RENDER only)
        derive.rs                    # map CLI status -> StatusState; bucket checkers by product/layer
                                     #   (bucketing, NOT verdict computation — see ADR-M1-002)
      timer.rs                       # doctor poll loop (~1h), one-in-flight, coalesce, backoff hook
      commands.rs                    # #[tauri::command] get_state(); emits `state-changed` events
    fixtures/                        # (dev/test) canned doctor corpus + mock `cc` stub (see §4)
      corpus/                        # *.json — one per status x product x layer + malformed cases
      mock-cc                        # executable stub: emits a selected corpus file as `doctor --json`
  src/                               # the TINY web UI (no framework; vanilla TS + a few web components)
    index.html                      # the popover document
    main.ts                         # subscribe to `state-changed`, call get_state(), render
    render/
      popover.ts                    # product-first list + inline four-layer expansion
      badges.ts                     # badge SHAPES (wrench/key/clock/triangle/dot/ring/bang/…)
      copy.ts                       # strings imported from 70-copy-voice (single source of truth)
      a11y.ts                       # role=tree/disclosure, live-region announcements, keyboard
    styles/tokens.css                # design tokens from 60-ui-design (colors/type/space/motion)
  package.json                       # minimal: tauri + a bundler; NO React/Vue/Svelte
```

**Rust <-> web-UI communication.** One `#[tauri::command] get_state() -> TrayStateDto` (UI pulls a
snapshot on open) plus one event `state-changed` (Rust pushes when a fresh doctor parse changes state).
The DTO is a serialize of the typed domain state (never the raw wire JSON — the UI never sees unparsed
CLI output, so it cannot accidentally re-interpret it). The web UI is render-only: it holds no state
machine, spawns no process, makes no verdict. All logic that could "decide" lives in Rust; all Rust
logic that could "compute ecosystem state" is forbidden and pushed to the CLI.

## 2. The parse-never-compute boundary (Rust)

Two layers, deliberately separated so the compute line is a type boundary:

1. **Wire layer** (`model/doctor.rs`, `model/envelope.rs`) — serde structs that mirror the schema
   exactly. `severity` and `destructive` are decoded through fail-closed adaptors, not raw `Option`:
   - `severity` missing/unknown  => `Severity::Fail`   (never `Pass`)
   - `destructive` missing        => `true`             (assume destructive)
   - `status` unknown-string      => routes to `StatusState::CliUnreadable` (not silently dropped)
   The struct for `checkers[]` keeps `additionalProperties` open (schema says so) but requires the three
   security-relevant fields; absence of any required field => the whole verdict is unreadable.

2. **Domain layer** (`model/state.rs`) — the typed `TrayState` the UI renders. Construction is the ONLY
   place a `StatusState` is chosen, and it is a MAPPING, never a computation:

   ```
   StatusState = {
     SetupNeeded, ItConfigIncomplete, Healthy, Syncing, UpdateAvailable, NeedsAttention,
     SignedOut, Offline, WaitingForNetwork, UpdatingApp,   // the 10 CLI-emitted states (mapped 1:1)
     CliUnreadable,                                          // the 11th, APP-OWNED, never CLI-emitted
   }
   ```

   - The tray glyph state = `map(doctor.status)` — a 1:1 lookup from the CLI's already-worst-wins
     top-level `status`. The app does NOT re-run a worst-wins ladder across hosts; the CLI already did.
   - `CliUnreadable` is chosen by the APP when, and only when: spawn failed / exit code 2 /
     JSON unparseable / `schema_version` out of the supported range (either direction) / a required
     security field is absent. It is fail-closed I/O handling, not ecosystem computation, and it
     OUTRANKS any partial `status` — a verdict we cannot trust is never rendered as its claimed state.

**Schema range-gate (bidirectional).** `envelope.rs` parses `schema_version` ("MAJOR.MINOR[.PATCH]")
into a comparable tuple and checks `MIN_SCHEMA <= v < MAX_SCHEMA_EXCLUSIVE` (an older schema is as fatal
as a newer one — invariant, per contract). MIN/MAX are compiled-in constants (Decision D-5 sets the
initial values). Out-of-range => `CliUnreadable`, with the copy "Versions don't match — click to update."

**Where the line is (for `me`):** ALLOWED = deserialize, apply fail-closed defaults, map the CLI's
`status` to a `StatusState`, bucket `checkers[]` by `(product, layer)` for display, pick attribution
text. FORBIDDEN = computing a health score, rolling a group of checkers up into a NEW 10-state status,
running a worst-wins ladder that produces a verdict the CLI didn't emit, any signature/merge/sync/wipe
logic. If a per-product or per-layer *status* is needed and the CLI doesn't emit one, that roll-up is
CLI work (Decision D-1) — the app must not synthesize it.

## 3. CLI-spawn design (`cli/path.rs`, `cli/spawn.rs`)

**Path resolution (translocation-safe), in order:**
1. Dev override: if `CT_CLI_PATH` is set (and, in release builds, only when a `--dev`/debug flag is
   compiled in), use it verbatim — this is how the mock `cc` is injected. Never consulted from a
   managed/forced domain; dev-only.
2. Release: resolve the vendored CLI **relative to the app bundle**, not $PATH — e.g.
   `Bundle/Contents/Resources/cc` via Tauri's resolved resource dir, then `canonicalize()` to defeat
   App Translocation (a randomized read-only mount path) and symlink games. NEVER a bare `cc`/`copilot`
   name (avoids the `gh copilot` shim collision and $PATH hijack). (Real vendoring is WS-D; M1 stubs
   this branch behind the resolver interface — Decision D-3.)
3. If neither resolves to an existing, executable, canonicalized absolute path => `CliUnreadable`
   ("couldn't start the engine"), never a fallback to $PATH.

**Invocation.** `Command::new(abs_path).arg("doctor").arg("--json")` with a hard timeout (kill on
expiry). Capture stdout (the JSON), stderr (diagnostics, never shown to Bob), and the exit status.

**Exit-code handling (maps to render state, never to a fabricated verdict):**
- `0` clean  => parse JSON; the rendered state is whatever the parsed `status` maps to (may still be a
  holding state).
- `1` any-fail => parse JSON; the CLI will have set `status` to a non-healthy value; render that.
- `2` env-error => do NOT trust any body; render `CliUnreadable`.
- spawn error / timeout / non-UTF8 / unparseable JSON / schema out of range / missing security field
  => `CliUnreadable`.

The current real `cc` is a Python venv shim (`/Volumes/.../claude-copilot/tools/cc/.venv/...python cc`)
on the unpushed `ws-a-doctor-slice` branch, and it does not yet implement `doctor --json`. M1 therefore
runs entirely off the mock (§4); the release resolver branch is interface-only until WS-A+WS-D land.

## 4. Mock-fixture strategy (`fixtures/`)

Drive the whole app off a canned corpus so every state is renderable without a real fleet.

- **Mock `cc` stub** (`fixtures/mock-cc`): a tiny executable that, on `doctor --json`, prints a selected
  corpus file to stdout and exits with the code encoded by that fixture (0/1/2). Selection via an env
  var (e.g. `CT_FIXTURE=signed-out-cli-dept`) so the running app can be flipped between states live.
  Exit-2 / non-JSON / truncated fixtures are produced by dedicated stub modes so the `CliUnreadable`
  path is exercised for real, not just unit-tested.
- **Corpus** (`fixtures/corpus/*.json`): one file per meaningful combination —
  - each of the 10 CLI `status` values, at least once;
  - every product (Knowledge, CLI, Claude, Codex) x every layer (foundation/org/department/personal)
    appearing as the worst item, so product-first grouping and four-layer expansion are all exercised;
  - a temporary department-project entry under a department layer;
  - the fail-closed set: missing `severity`, missing `destructive`, missing required field, malformed
    `schema_version`, schema below MIN, schema above MAX, exit code 2 body, truncated/non-JSON.
  Valid fixtures are asserted against `doctor.schema.json` in CI; the intentionally-invalid ones are
  asserted to map to `CliUnreadable` (and are excluded from the schema-valid set).
- **Injection.** `CT_CLI_PATH=fixtures/mock-cc` selects the stub; `CT_FIXTURE=...` selects the state.
  The web UI additionally supports a static-fixture mode (import corpus JSON, run through the same DTO
  shape) so UI work (`uid`) is unblocked before the Rust timer (T5) lands.

## ADR-M1-001: Render the CLI's `status`; never compute a verdict in Rust
**Status:** Accepted
**Context:** The product's #1 failure mode is a false-Healthy. The CLI emits a single worst-wins,
per-host `status`; the app is a face over it.
**Decision:** The tray glyph state is a 1:1 map of `doctor.status`. Rust runs no health scoring and no
worst-wins ladder of its own. The only app-authored state is `CliUnreadable`, chosen purely from I/O /
schema failure, which fail-closes over any untrusted body.
**Consequences:** Easier — a false-Healthy is structurally impossible (no code path constructs Healthy
except `map(status==healthy)` on a schema-valid, in-range, non-offline, fully-authed verdict). Harder —
the app is at the mercy of the CLI's `status` correctness; the CI contract test upstream is the
backstop. Reversible? Yes (mapping table). Optimizing: honesty. Sacrificing: any offline "best guess".
**Alternatives rejected:** Compute a status from `checkers[]`/`score` in Rust — rejected: it is exactly
the second-brain the invariants forbid and the most likely source of a false green.

## ADR-M1-002: Product/layer badges are BUCKETING, not roll-up computation
**Status:** Proposed (blocks on Decision D-1)
**Context:** The design shows a per-product badge (worst of its 4 layers) and per-layer badges, but
`doctor.schema.json` emits only ONE top-level `status` plus per-checker `severity` — there is no
per-product or per-layer rolled-up `status` field.
**Decision:** For M1 the app renders per-(product,layer) badges from the **worst per-checker `severity`
present in that bucket** (a min/max over already-CLI-computed verdicts — presentation), and NEVER
synthesizes a new 10-state `status` per product/layer. Grouping = `checkers.group_by(product, layer)`.
The rich per-layer *status* (e.g. "updating in the background") is rendered ONLY if the CLI supplies it
(future field); otherwise the layer shows the raw severity badge (pass/warn/fail shape) + attribution.
**Consequences:** Easier — no verdict computation sneaks in; the badge is honestly "worst finding here".
Harder — the layer phrasing is coarser than the copy deck until the CLI emits per-layer status. It is
the safe, fail-closed floor. Reversible? Yes.
**Alternatives rejected:** Have Rust map bucket-severity -> the 10-state enum per layer — rejected as
verdict computation (invariant #1). This is escalated as Decision D-1: the CLI should emit per-product
and per-layer status so the app can render the full copy deck without computing.

## ADR-M1-003: Absolute bundle-relative CLI path + dev-only env override
**Status:** Accepted
**Context:** Bare `copilot` collides with GitHub's `gh copilot`; $PATH is hijackable; macOS App
Translocation randomizes the bundle mount path.
**Decision:** Release resolves the CLI relative to the app bundle's resource dir and `canonicalize()`s
it; dev uses `CT_CLI_PATH` (compiled-in dev flag only). Never a bare name, never $PATH.
**Consequences:** Easier — translocation- and hijack-safe; testable via the override. Harder — depends
on WS-D vendoring for the real path (stubbed in M1). Reversible? Yes.
**Alternatives rejected:** Resolve via $PATH / `which` — rejected (hijack + `gh copilot` collision).

## ADR-M1-004: Single Tauri process, Accessory activation, no daemon
**Status:** Accepted
**Context:** Invariant #2 — one binary = tray + timer; the CLI self-serializes via flock; launchd (out
of M1 scope) is a crash-only watchdog.
**Decision:** One Tauri process, `ActivationPolicy::Accessory` (LSUIElement), single-instance, popover
window hidden by default. The doctor timer runs on a Tokio task inside this process. No second process,
no in-app fallback loop.
**Consequences:** Easier — nothing to keep two processes consistent; future `KeepAlive={SuccessfulExit:
false}` watchdog is not precluded (RunAtLoad stays false; clean Quit stays quit). Harder — a crash takes
the tray down until the (future) watchdog restarts it. Reversible? Yes.
**Alternatives rejected:** Separate daemon + tray client — rejected (invariant #2; double-write and
consistency risk).

## Fitness functions (define now, enforce in CI)
- **No-fabricated-Healthy:** a test asserts `StatusState::Healthy` is constructed at exactly one call
  site, guarded by `status == healthy` on a schema-valid, in-range, non-offline verdict; grep/AST lint
  fails the build if `Healthy` is constructed elsewhere.
- **Fail-closed corpus:** every intentionally-invalid fixture maps to `CliUnreadable`; every valid
  fixture round-trips and renders its mapped state (no panics, no `Healthy` unless the fixture says so).
- **No-compute boundary:** `render/` and `model/` contain no arithmetic on `score`, no severity->status
  synthesis; a lint denies importing scoring/merge crates.
- **No bare CLI name:** grep denies `Command::new("cc"|"copilot")`; the only spawn goes through
  `cli::path::resolve()`.
- **Thin skin:** `package.json` denies React/Vue/Svelte/Angular; UI bundle size budget enforced.
