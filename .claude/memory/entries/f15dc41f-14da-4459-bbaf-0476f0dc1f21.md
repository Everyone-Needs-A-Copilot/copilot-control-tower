Notarization credential doctrine (2026-08-06): ct-notary is a standing credential on Pablo’s publisher Mac. Apple notarytool uses the macOS Data Protection Keychain unless an explicit file-based --keychain is supplied. Therefore security find-generic-password against login.keychain-db can say not found while xcrun notarytool history --keychain-profile ct-notary succeeds. Treat a local No Keychain password item found as profile unavailable to that process, never as proof of deletion. Retry the authoritative notarytool history probe and re-run it from the logged-in user’s fresh Terminal if needed. If any later probe succeeds, continue the release without asking for a new password or rerunning Publisher Setup. Only repeated logged-in-user failures with no later success justify unavailable; remote HTTP 401 is credential rejection, not missing Keychain data. Release automation must preflight before expensive builds and retry only this transient lookup class without bypassing notarization or verification.
