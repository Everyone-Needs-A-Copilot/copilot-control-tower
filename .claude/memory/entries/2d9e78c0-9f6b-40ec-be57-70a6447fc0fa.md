Copilot Control Tower M5 QA (task 50): mutation-testing fitness tests live (not just reading them) catches real gaps a read-only review misses - inserting a genuine remove_dir_all/CFPreferencesCopyAppValue string into production code and confirming the fitness test fails, then restoring byte-for-byte via diff-verified backup, is cheap (~1min) and proves FF-M5-1/FF-M5-2 aren't tautological. Also: a 'strings' scan of a release binary can false-positive on adjacent Rust string constants with no null separator merging into one apparent match, AND a stale target/release binary (built before the session's own touch+rebuild) can silently linger if only the lib recompiles without relinking the bin - always rm the binary + deps/<binname>-* and do a clean cargo build --release --bin <name> before trusting a strings scan. Also: when a task's own filed tc task metadata names specific deliverable files (e.g. a consolidated fitness_m5_suite.rs + integration_m5_managed_deprovision.rs) that the actual QA-session prompt doesn't ask for, check the filesystem/git status for them anyway and flag as a scope gap (D1-style) rather than silently ignoring the mismatch - functional coverage via separate files can still fully satisfy the invariants even if the literally-named file never got built.
