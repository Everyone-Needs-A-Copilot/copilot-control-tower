T3 doctor model: missing security fields (severity/destructive/id on checkers; identity/scope/state on auth) fail the WHOLE verdict closed to CliUnreadable(missing_security_field), not a per-field default — this matches doctor.schema.json's required list and the T2 fixture corpus (checker-missing-severity/destructive.json). A field that's PRESENT but an unrecognized value (e.g. a future severity string) fails closed to the worst known value (severity->Fail, auth.state->Revoked) instead of rejecting the whole body. CliStatus::Healthy is constructed at exactly one call site (model::state::parse_cli_status); everywhere else uses CliStatus::is_healthy()/glyph_badge() (Self::-prefixed) so a grep-based fitness test (tests/fitness_no_fabricated_healthy.rs) can prove it. RenderState lives in render::derive and mirrors src/types.ts (already scaffolded by T1) byte-for-byte.
