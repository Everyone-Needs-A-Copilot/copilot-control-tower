M4 S4+S5 (update-check client + updater IPC + COPILOT_MANAGED_BY): updater::check.rs owns the transport — FeedFetcher trait (sync, DI'd like watchdog::HeartbeatSource) with LocalDirFetcher (dev/test, CT_UPDATE_FEED env override mirroring CT_CLI_PATH's cfg(any(debug_assertions,test)) release-safety shape) and HttpFetcher (production, reqwest::blocking — added as an explicit direct dep with default-features=false + blocking+rustls features; reqwest was already a transitive dep of tauri core so this adds zero new crates to the graph, just enables blocking). Design decision: check_for_update() downloads manifest+signature+artifact and calls the REAL verify::verify_update (never a duplicate/independent signature-peek, even though fixtures carry an unused artifact_url field) — deliberately trades check-time bandwidth for zero duplicate crypto verification code outside sec's frozen verify.rs; flagged as a follow-up (a manifest-only-verify helper in verify.rs) once the real D-4-M4 feed exists and artifact size makes this matter. VerifyError::Downgrade maps to UpdateStatus::UpToDate (not Error) since a same-or-older signed manifest is 'nothing to update', not a failure. apply_update() stages verified bytes into do's StagedLayout (VERSION + artifact.bin), then fail-closed offline-staples via verify::verify_staple before ever reporting Ready — a failed staple discards the staged dir immediately (never leaves an unstapled bundle for the watchdog's promote/rollback to find). IPC: commands::check_for_update/apply_update are async, spawn_blocking-wrapped (reqwest::blocking would panic inside Tauri's own async runtime otherwise) — both zero-arg, returning UpdateState DTO (updater::dto.rs, mirrors src/types.ts's S10-frozen shape exactly, kebab-case status enum). Capability: allow-check-for-update/allow-apply-update added to capabilities/default.json (popover) + build.rs's AppManifest.commands (ACL enforcement requires both). COPILOT_MANAGED_BY=controltower wired via .env() on cli::spawn::doctor's Command (ADR-M4-005, single-owner of vendored cc) — scoped to that one spawn site per task brief, not the wizard's other Command::new call sites (materialize.rs/persistence.rs/signin.rs), which is a deliberate scope boundary, not an oversight, flagged for a follow-up task to widen consistently if desired. settings::guard::DENIED_KEYS gained 'updatechannel' (M2 gap sec found) alongside existing updatefeedurl/allowselfupdate.
