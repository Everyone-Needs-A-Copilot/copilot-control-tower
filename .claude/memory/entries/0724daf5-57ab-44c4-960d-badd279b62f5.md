M9 Streams E+H (tasks 74, 77): Windows managed login-item + CLI path/hijack hardening.

Implemented platform/windows/loginitem.rs (Stream-E, task 74) and platform/windows/cli_path.rs (Stream-H, task 77), both #![cfg(windows)]-gated (never compiled/run here -- no Windows toolchain).

Stream-E (loginitem.rs): WindowsLoginItem implements PlatformLoginItem via a per-user Task Scheduler LOGON-trigger task (packaging/taskscheduler/logon-task.xml, new template, __APP_PATH__ substituted at register()-time), consuming schtasks.rs read-only. Deliberately rejected the HKCU\...\Run key alternative windows-parity.md names as "the simpler fallback" -- a Bob can delete a Run value with regedit, defeating the whole point; only a GPO/Intune-required scheduled task is genuinely non-toggleable. Key design divergence from macOS: gating is FOLDED INTO register() itself (calls crate::loginitem::decide_enablement().should_register(), no-op if false) rather than one-level-up like macOS's loginitem::mod::install(), because Task Scheduler (unlike SMAppService) has no OS-native consent/force-approval gate of its own. Reuses the EXISTING cross-platform decide_enablement()/managed::forced::forced_bool (already has a fail-closed #[cfg(not(target_os="macos"))] stub) rather than reimplementing forced-domain reading -- picks up Stream-D's eventual real HKLM read with zero code change here once task 73 lands. unregister() stays unconditional; status() maps schtasks::query_task_exists via a pure probe_to_status fn (Ok(true)->Enabled, Ok(false)/Err->NotFound, fail-closed, no RequiresApproval on Windows). Documents the ADR-M5-004 delineation from watchdog.rs (Stream-C's separate crash-restart task, different task name, no RestartOnFailure element in this task's XML).

Stream-H (cli_path.rs): resolve() order = dev override (CT_CLI_PATH, same env var name as macOS, gated debug_assertions/test/dev-seam) -> current_exe()-relative (primary, cc.exe sibling to the running exe, canonicalized, needs no MSI) -> HKCU registry InstallLocation fallback (owner-gated, needs Stream-I's MSI, task 78) -> NotInstalled. Never reads %PATH%. DLL-hijack hardening: harden_dll_search_path() calls SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_DEFAULT_DIRS) (Once-guarded, idempotent) to strip cwd from the DLL search order -- added Win32_System_LibraryLoader feature to Cargo.toml's cfg(windows) windows-crate deps for this (documented as owner-gated-to-reverify binding signature).

2 new fitness tests (compile+run on macOS, source-scan style): fitness_m9_windows_cli_path_no_path_env.rs (denies var("PATH")/var_os("PATH") case variants + denies Command::new() in cli_path.rs + confirms DEV_OVERRIDE_ENV stays gated) and fitness_m9_windows_loginitem_gated_on_managed_config.rs (extracts register()'s fn body text, asserts decide_enablement/should_register appear BEFORE create_task_from_xml; asserts unregister() never references the gate; asserts loginitem.rs never imports winreg/RegKey directly).

Verification: macOS cargo build/test/clippy(debug+release, -D warnings)/fmt --check all green (841 tests total, 0 failed, using PATH=/usr/bin:$PATH CC=/usr/bin/cc workaround). Windows compile/run explicitly NOT claimed -- owner-gated, cfg(windows) compiles this out on macOS entirely; only fmt parses it.
