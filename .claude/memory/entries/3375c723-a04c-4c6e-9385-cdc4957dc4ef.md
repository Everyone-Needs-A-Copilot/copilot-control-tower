T4 CLI-spawn boundary (src-tauri/src/cli/): path.rs resolves cc absolute path via CT_CLI_PATH dev override (#[cfg(debug_assertions)]-gated, compiled OUT of release builds entirely) or production branch derived from std::env::current_exe().canonicalize() walking up to Contents/Resources/cc (translocation-safe, no argv[0]/cwd dependency); WS-D vendoring not landed so production branch always returns PathError::NotVendored today (interface-only, Decision D-3). spawn.rs runs <path> doctor --json with a 15s hard timeout via poll-loop + process_group(0) + SIGKILL to the whole pgid on timeout (plain child.kill() left an orphaned grandchild holding the stdout pipe open, defeating the timeout — this was caught by a real test failure, not by inspection). Exit 0/1 both route through parse_doctor_body unchanged (T3 re-verifies content regardless of exit code, per the poisoned-body-on-exit-0 adversarial case); exit 2 and any other outcome map to CliUnreadableReason::IoError/Exit2. cli::run_doctor() -> RenderState is the T5 timer entry point. All CT_CLI_PATH/CT_FIXTURE-mutating tests across cli::path/cli::spawn/cli::mod share one process-global Mutex (cli::test_env::ENV_LOCK) since cargo test runs in parallel and env vars are process-global.
