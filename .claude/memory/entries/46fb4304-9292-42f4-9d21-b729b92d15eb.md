Implemented item #2a (copilot update mirror-sync CORE, V-3/V-4 onboarding blocker) in cli-copilot/copilot_cli/config/sync.py + main.py's new 'update' Typer command. Scope: concrete refs (branch/tag/SHA) + never-destroy gate + human-readable output only -- semver-range ref RESOLUTION and --json payload deferred to #2b.

Key decisions:
1. Never-destroy gate uses GitClient.status()'s staged/modified/not_added/deleted/conflicted fields -- any non-empty = dirty = HELD, zero writes; fail-safe extended to "mirror root exists but is not a git repo" (held, not cloned-into) and to any exception raised by status() itself.
2. is_semver_range() detects a caret/tilde prefix or a range operator (comparison signs, double-pipe) per spec, deliberately narrow so concrete refs like "main", "v1.x", or a 40-char SHA never false-positive.
3. Dropped the "up-to-date" vs "pulled (n commits)" distinction from the output spec: verified empirically that GitPython's FetchInfo note and flags fields are always empty/zero in this environment via GitClient.pull(), so that distinction can't be made honestly through the three approved GitClient methods (clone/pull/status) alone without extra plumbing. Flagged as a fast-follow if precise commit-delta reporting is wanted later (would need GitClient.pull() itself extended, out of #2a scope).
4. SHA refs are treated as "concrete" (not a range) and passed through to GitClient.clone/pull's branch kwarg as-is; a bare SHA will currently surface as an "error" result (not a crash) since git clone --branch <sha> doesn't resolve arbitrary commits and GitClient has no standalone checkout primitive -- acceptable for #2a since only branch/tag refs are exercised by the live manifest and tests, but a known gap for true SHA support.

Tests: 14 unit (tests/test_config/test_sync.py) + 5 CLI-level (tests/test_cli.py, including an end-to-end V-3 hold-dirty proof through the real "copilot update" command) = 19 new tests, all passing; full suite went from 892 to 911 passed / 10 skipped, zero regressions. All tests use file:// local remotes plus COPILOT_MIRRORS_ROOT / COPILOT_LAYERS_FILE env overrides into tmp_path -- confirmed the real ~/.copilot/mirrors and ~/.config/copilot/copilot.layers.yml were untouched (md5 / dir-listing diffed before and after).
