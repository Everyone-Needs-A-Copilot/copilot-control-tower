Org-tier config migration (regen-safe org mirror, PRD-12/tasks 130-135): org mirror .env is a SYMLINK to the gitignored working-tree .env, so copilot update (git clone) would drop all 39 keys and break CLI+bridge+services. Two consumer classes: Class-1 layered Settings (TierConfigSource=non-secret, SecretRefSource/ladder=secret) vs Class-2 self-contained loaders (infisical InfisicalSettings, coolify APIConfig) that bypass the chain and read env/.env/TOML directly. KEY MECHANISM GAP: TierConfigSource reads adopt[].config ONLY; OverlayProvide has no config field and the YAML parser silently drops config: on provides entries (layers.py:463-475) -> non-secret config for the 8 provides services (n8n/nocodb/discord/insights/project/conv/brevo/coolify) cannot be committed until we extend the schema (ADR-001, the prerequisite/foundation task). requires_secret on provides ALREADY works (all_requires_secret spans provides). Findings: 15 keys DEAD (no CLI consumer, only doc/test mentions); 6 non-secret keys == field default -> just drop; SHELL_SCRIPTS_PATH is a machine-specific absolute path -> never commit to shared org config; coolify token requires_secret is INERT (self-contained) -> ADR-002 owner decision (loader-consults-ladder vs coolify TOML/keychain). Full ADR + 39-key table = WP-79 on task 130.
