Control Tower M2 S2 (config_pointer.rs): the layers.manifest config-pointer write shells to 'cc config set layers.manifest <path>' (D-5-M2) via the SAME dev-mockable seam cli::path::resolve() uses for doctor (CT_CLI_PATH in debug/test, vendored bundle path in prod) — no JSON dotted-set replicated in Rust. cli::path::resolve() failure (not vendored yet) maps to ConfigPointerError::CliUnavailable, an honest state never a crash/false-success. Tests mock the seam with a throwaway shell script (local to config_pointer.rs's own tests, not the shared fixtures/mock-cc which only implements 'doctor') that logs argv to a file and asserts on it. NOTE for future review: config_pointer.rs constructs Command::new(cli_path) directly rather than routing through cli::spawn — this is narrower than cli/mod.rs's documented 'only cli::spawn constructs Command for the CLI' invariant (though it doesn't trip the actual fitness_no_bare_cli_name.rs grep test, which only forbids the doctor-shaped invocation outside cli/spawn.rs). Left as-is because the S2 task scope explicitly forbade editing cli/ files; a follow-up could add a cli::spawn::config_set() and route through it for full consistency.
