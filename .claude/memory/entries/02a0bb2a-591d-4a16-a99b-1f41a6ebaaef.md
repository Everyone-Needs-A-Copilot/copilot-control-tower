claim_sweep.py's ±1-line annotation window can over-back unrelated assertions: a single <!-- claim-check: id --> on a table row backs EVERY matched category on the line above/below too, even topically unrelated ones (e.g. claude-copilot's framework-restructure-2026-04.md: model-tier-opus-dominant-main-session's annotation on the 'Model cost' row also marks the adjacent 'Agent roster | 14 agents | 8 agents' row's COUNT_UNIT hits as BACKED, though that claim never tests roster size). The tool's own precision_caveat in claims.yaml documents false positives (non-claims flagged UNBACKED) and false negatives (invisible assertions) but not this third failure mode: false BACKED via line-proximity to an unrelated annotation. Recommend documenting this explicitly or tightening backing to same-line-only for multi-assertion lines/rows.
