M2 S6: save_settings/get_settings are thin #[tauri::command] wrappers around testable core fns (get_settings_at/save_settings_at) that take an explicit path + (for save) an injected repoll closure -- lets cargo test drive the full author->guard->write->pointer->repoll pipeline against temp dirs with zero live AppHandle/DoctorState/tray, using tauri::async_runtime::block_on (self-initializing default runtime) to run the async fn synchronously in tests. Re-poll only fires on a FULLY successful save (manifest write AND pointer set both succeeded) -- a pointer failure skips repoll since cc wouldn't see the new config anyway. Empty inputs is a pure no-op (never a false 'no layers declared' error on an untouched first-run save). get_settings never surfaces the manifest-wide 'no layers declared' validate error (empty layers = the ordinary first-run/empty state, the UI already renders its own empty-state copy for that).
