Re-minting is blocked: the ONLY Infisical credential anywhere on this Mac (keychain, .env, shared-docs) is the broken pair itself -- no admin token exists locally, and the existing runbook already documents identity minting as a human-only dashboard step (no provisioning verb). Rejected hand-rolling a DB-level identity mint via Coolify SSH+docker-exec (Infisical's postgres is compose-service-scoped, not a standalone db resource, and bypassing Infisical's own hashing/RBAC to write identity rows is an unreversible manual-prod-change antipattern) -- correctly escalating to the owner instead of guessing. Also surfaced a scope concern for whoever re-mints: this machine's CLI exposes infisical identity create/delete + org disable-signup, implying its old identity may have held broader-than-RD-1 read-only privilege -- worth tightening on re-mint, not just restoring. Apple/notary-secret bonus sweep: Coolify side clean for all 6 compose services (checked via safe name-only docker_compose declarations); did NOT sweep the 24 standalone apps because coolify envvar list has no names-only mode (prints live values) -- confirmed the hard way (see incident). Incident: a misplaced --json flag order made 'coolify envvar list' render its live table instead of JSON for one app (Automation Copilot/n8n), exposing two truncated (~20-char prefix) values (N8N_ENCRYPTION_KEY, DB_POSTGRESDB_PASSWORD) in tool output -- disclosed to owner, recommend rotating those two out of caution. Lesson: coolify's --json is a group-level flag that must sit between 'coolify' and the subcommand (copilot coolify --json <cmd>), not before 'coolify' -- placing it earlier is silently ignored for some subcommands (diag issues, monitor health, envvar list) while appearing to work for others (app list, svc list), and envvar list has no safe presence-only path at all.
