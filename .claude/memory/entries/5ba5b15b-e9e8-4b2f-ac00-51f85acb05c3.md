M3 mock-cc auth seam (TASK-29): the device-flow seam is 2 payloads only -- initiate={user_code,verification_uri,expires_in,interval} (canned, same for every scenario since outcome hasn't happened yet) and poll={status} (authorized|denied|expired|timeout|pending), enforced as an exactly-these-keys check in fixtures/wizard/validate.py. Exit codes are binary for auth (0 normal incl. denied/expired/timeout/pending, 2 env-error) -- unlike doctor's 0/1/2, there is no per-checker severity concept for auth. The 3 honest sign-in failure variants (denied/expired/timeout) all converge on reusing doctor's EXISTING signed-out render (corpus/signed-out-claude-personal.json) rather than inventing a new holding terminal -- avoids a raw OAuth error string per the Git-Error-To-A-Non-Technical-Person discipline. One adversarial mock scenario (CT_AUTH_SCENARIO=authorized-leaked-field-adversarial) intentionally emits an obviously-fake access_token field so Stream-A's Rust parser can be proven (fitness fn 2, no-secret-on-wizard-DTO) to drop/ignore unknown fields rather than forward them -- the constant value is asserted verbatim in validate.py so it can never quietly become realistic-looking.
