Token-premium ablations must match model AND task-realism, not just materialize the same files: WP-77's scaffold ablation (haiku, trivial no-tool prompt) measured a real 2,124-token scaffold cost, but the live ladder (sonnet, real tool-using job briefs) shows a ~3,400-3,600 token premium per cell. The gap (~1,300 tokens, ~38% of the premium) is concentrated entirely in turn 1 (session start), ruling out 'extra work over multiple turns' -- but is NOT explained by extra file materialization either (configs.py confirmed identical scaffold across both). It is most likely a model (sonnet vs haiku) x real-prompt confound between the two measurements. Lesson: when validating a fixed-cost claim via ablation, match the model and use a representative (not trivial) prompt, or the isolated delta will systematically undercount the effect it's meant to explain.
