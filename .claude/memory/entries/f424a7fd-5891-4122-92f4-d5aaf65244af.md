Retryability (task 210/G-7) is a HoldingInfo.retryable Bool computed ONLY inside WizardModel.holdingInfo(forBlockedOnboard:) from resume.safe_to_rerun AND the blocked stage's own layer action/sync_state -- never from resume.safe_to_rerun alone, since the real CLI's _resume_hint always returns true (it answers 'is retrying safe', not 'will retrying help'). A new 'visible-repositories' stage case (the closed Git-history classifier's review rows: ahead/diverged/diverged-identical/local-changes/wrong-origin/unreadable) forces retryable=false and composes a specific 'reviewRepositoryPhrase' naming the repo+state instead of falling into the generic H3 default. h2View/h3View's primary 'Try again' button now gates on info.retryable, falling back to 'Continue in the menu bar' when false.
